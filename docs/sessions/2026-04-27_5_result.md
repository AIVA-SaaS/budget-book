## 회고

### 진단 단계의 비용
- 회차 4 의 sentinel 도입 후 `_prefillFromTransaction` 에 ADJUSTMENT 분기 추가했으나, **`_loadTransaction` 이 별도로 인라인 prefill 하던 사실을 놓침** → "+-1" 표시 fix(#199) 후에도 "감소 → 수정 시 -1 표시 + 라디오 충돌" 회귀 잔존.
- prefill 진입점 다중화는 회차 4 시점에 grep 으로 잡아낼 수 있었으나 detail page 만 보고 form_page 는 회귀 없음으로 가정한 게 원인.

### audit-patterns 효과
- v1.7.0 `signed_amount_display` 가 raw amount + EXPENSE/INCOME ternary grep 으로 detail page 외 다른 표시 위치(통계, dashboard 등) 도 사전 점검 강제.
- 향후 prefill 진입점 통일 정책도 `state_preservation_on_refresh` 와 묶어 점검 가능.

### 플로우 개선
- ADJUSTMENT 같은 special type 도입 시 영향 영역 grep 체크리스트:
  1. 표시 위치 (list, detail, summary, 통계, dashboard)
  2. prefill 진입점 (form initState, _prefillFromTransaction, _loadTransaction, _loadCopyFromTransaction)
  3. submit 변환 (helper)
  4. validation (BE + FE)
- 이번 시리즈 회귀로 #1, #2 모두 다중 진입점 패턴 확인됨. audit 자동 grep 으로 향후 사전 차단.

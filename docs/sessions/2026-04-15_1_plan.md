# Phase 20: 카드 결제 현황 월 동기화 + 결제 금액 표시 + 네비게이션 월 전달 수정
> 날짜: 2026-04-15 | 회차: 1 | 상태: 기획검증완료

## 요청 내용
1. **카드 사용 금액이 월 이동해도 모두 동일** — 결제수단 관리 페이지에서 월을 변경해도 카드 결제 현황 금액이 변하지 않음
2. **카드 결제 시 0원만 나옴** — 카드 결제 페이지에서 전월 사용액과 결제 대상 거래가 0원으로 표시됨. 현재 선택한 달의 이전달 미결제 항목과 금액이 표시되어야 하며, 항목 선택/금액 수동 수정/항목 연결 선택이 필요
3. **다른 탭에서 월 이동 후 거래 내역 이동 시 현재 월로 필터링됨** — 홈/예산/통계 등에서 10개월 전을 보다가 거래 상세로 이동하면, 현재 월 내역으로 돌아가서 다시 이동해야 함

## 영향 범위 분석

### Bug 1: 카드 결제 현황 월 미동기화
- **원인**: `payment_method_page.dart`에 월 네비게이터가 없음. 카드 결제 현황은 `LoadPaymentMethods` 성공 시 `add(const LoadCardSettlementSummary())` → year/month 없이 호출 → BE에서 `YearMonth.now()` 사용
- **핵심 파일**: 
  - `payment_method_page.dart` — 월 네비게이터 추가 필요
  - `payment_method_bloc.dart:35` — year/month 전달
  - `payment_method_event.dart` — LoadCardSettlementSummary에 year/month 필수화
  - `payment_method_state.dart` — year/month 상태 보존

### Bug 2: 카드 결제 금액 0원
- **원인**: `card_settlement_page.dart:92-98`에서 `_loadSettlement()`이 현재 선택 월의 `settlementDate` 범위로 거래를 조회
- **BE 로직 확인**: `TransactionService.getSettlementTransactions()` (line 368-393) — `findByPaymentMethodAndSettlementDateRange`로 해당 월의 settlementDate인 거래를 찾음. 이는 정상
- **settlementDate 계산**: `calculateSettlementDate()` (line 395-409) — closingDay 이전 거래→다음달, 이후 거래→다다음달
- **0원 가능 원인**: (1) 카드에 closingDay/settlementDay 미설정 → settlementDate = null, (2) 기존 거래에 settlementDate 미계산 저장
- **핵심 파일**:
  - `TransactionService.kt:395-409` — calculateSettlementDate() 로직
  - `card_settlement_page.dart` — 전월 사용액 표시 방식 개선
  - `card_settlement_bloc.dart` — 전월 사용 금액도 함께 표시

### Bug 3: 네비게이션 월 전달 누락
- **원인**: 여러 화면에서 거래 목록/상세로 이동 시 year/month context를 전달하지 않음
- **핵심 파일**:
  - `dashboard_page.dart:667` — `/transactions/detail/${txn.id}` (월 미전달)
  - `dashboard_page.dart:638` — `context.go('/transactions')` (월 미전달)
  - `dashboard_page.dart:1157` — `context.go('/transactions?categoryId=...')` (year/month 누락)
  - `transaction_detail_page.dart:66` — `context.go('/transactions')` (월 미전달)
  - `transaction_form_page.dart:472` — `context.go('/transactions')` (수정 완료 후 월 미전달)
  - `app_router.dart:277-281` — 라우트 빌더의 year/month 폴백 로직

### [filter_propagation] 발견사항

## 기획 검증 결과

### Bug 1 검증
- `PaymentMethodService.getCardSettlementSummary()`는 `year`/`month` 파라미터를 받으면 해당 월 기준으로 정상 계산 → BE 수정 불필요
- FE `payment_method_page.dart`에 월 네비게이터 추가 + `LoadCardSettlementSummary`에 year/month 전달만 하면 해결

### Bug 2 검증
- BE `getSettlementTransactions()`는 `settlementDate` 기준으로 거래 조회 → 4월 선택 시 settlementDate가 4월인 거래(= 3월에 사용한 카드)를 정확히 반환하는 구조
- `calculateSettlementDate()` — closingDay 이전 거래 → 다음 달 결제, 이후 거래 → 다다음 달 결제
- **0원 원인 가능성**: (1) 카드에 closingDay/settlementDay 미설정 → settlementDate=null, (2) 기존 거래에 settlementDate 미저장
- 실제 DB 데이터 확인 필요: 거래 테이블의 settlement_date 컬럼에 값이 있는지

### Bug 3 검증 (하네스 강화)
- 하네스 scope audit으로 5개 네비게이션 누락 지점 발견 (기존 분석 2개 → 5개로 확장)
- 과거 동일 패턴 사건(2026-04-14) 매칭 확인
- 모든 지점에서 현재 context의 year/month를 일관되게 전달하는 방식으로 수정

### 이슈 #1 — 기간 필터 즉시 적용 (UX 비대칭)
- 위치: `frontend/lib/core/widgets/filters/unified_filter_bar.dart:244~272`
- 현재 동작: "기간 변경" 클릭 → `showDateRangeFilterSheet` 의 프리셋 탭 → 외부 시트도 `Navigator.pop(ctx)` + 즉시 `onFilterChanged(state.copyWith(dateFrom..., dateTo..., dateRangeLabel:...))` 호출

## 설계 결정

### A. 기간 필터 임시값 관리
```dart
// 시트 시작 시
DateTime? tempDateFrom = state.dateFrom;
DateTime? tempDateTo = state.dateTo;
String? tempDateRangeLabel = state.dateRangeLabel;
bool tempDateCleared = false;  // X 버튼 누른 케이스 추적

// 기간 변경 onApply
showDateRangeFilterSheet(
  ...,
  onApply: (label, from, to) {
    setSheetState(() {
      tempDateFrom = from;
      tempDateTo = to;
      tempDateRangeLabel = label;
      tempDateCleared = false;
    });
    // ❌ 외부 시트 pop 제거, ❌ onFilterChanged 호출 제거
  },
  onClear: () {
    setSheetState(() => tempDateCleared = true);  // 외부 시트는 유지
  },
);

// 옆 X 버튼
onPressed: () => setSheetState(() => tempDateCleared = true),

// "적용" 버튼 안
onFilterChanged(UnifiedFilterState(
  dateFrom: tempDateCleared ? null : tempDateFrom,
  dateTo: tempDateCleared ? null : tempDateTo,
  dateRangeLabel: tempDateCleared ? null : tempDateRangeLabel,
  ... (나머지 기존 그대로)
));
```

기간 필드 표시(line 234-245)도 `tempDateFrom/tempDateRangeLabel` 기준으로 변경 — 사용자가 "이번 주" 선택 시 시트 안에서 즉시 라벨이 갱신됨. 단 부모(state) 는 "적용" 전까지 변하지 않음.

### B. CategoryFilter 통일
```dart
class CategoryFilter extends StatelessWidget {
  final String? selectedCategoryId;
  final String? selectedCategoryName;
  final String categoryType;
  final void Function(String? id, String? name) onChanged;

  @override
  Widget build(BuildContext context) {
    return ItemSelectorField(
      label: '카테고리',
      selectedLabel: selectedCategoryName,
      prefixIcon: Icons.category,
      placeholder: '전체',
      onTap: () => showDialog(  // 기존엔 showModalBottomSheet — dialog로 통일
        context: context,
        builder: (_) => CategoryGroupSelectorSheet(
          selectedCategoryId: selectedCategoryId,
          categoryType: categoryType,
          onSelected: (_) {},
          onSelectedWithGroupName: (cat, groupName) {
            final id = cat?.id;
            final name = cat != null
                ? (groupName != null ? '$groupName > ${cat.name}' : cat.name)
                : null;
            WidgetsBinding.instance.addPostFrameCallback((_) {
              onChanged(id, name);
            });
          },
        ),
      ),
    );
  }
}
```

거래 폼과 동일하게 `showDialog` 사용 (기존엔 `showModalBottomSheet` — dialog가 nested context 안전성↑).

### C. PaymentMethodFilter 통일
```dart
class PaymentMethodFilter extends StatelessWidget {
  final String? selectedId;
  final ValueChanged<String?> onChanged;
  // 신규: 표시명 콜백 — UnifiedFilterBar 가 paymentMethodName 도 함께 받도록
  final void Function(String? id, String? name)? onChangedWithName;

  @override
  Widget build(BuildContext context) {
    return BlocBuilder<PaymentMethodBloc, PaymentMethodState>(
      builder: (context, pmState) {
        final methods = pmState is PaymentMethodLoaded
            ? pmState.activePaymentMethods
            : <PaymentMethod>[];
        final selectedName = selectedId != null
            ? methods.where((pm) => pm.id == selectedId).map((pm) => pm.name).firstOrNull
            : null;

        return ItemSelectorField(
          label: '결제수단',
          selectedLabel: selectedName,
          prefixIcon: Icons.account_balance_wallet,
          placeholder: '전체',
          onTap: () => showDialog(
            context: context,
            builder: (_) => ItemSelectorSheet(
              title: '결제수단 선택',
              items: methods.indexed.map((e) => SelectorItem(
                id: e.$2.id,
                label: e.$2.name,
                leadingIcon: paymentMethodTypeIcon(e.$2.type),
                leadingColor: paymentMethodTypeColor(e.$2.type),
                isDeletable: false,  // 필터 sheet 에선 삭제 불가
                displayOrder: e.$1,
                group: e.$2.type,
              )).toList(),
              selectedId: selectedId,
              nullLabel: '전체',
              favoriteType: 'PAYMENT_METHOD',
              groupLabels: paymentMethodGroupLabels,
              onSelected: (item) {
                onChangedWithName?.call(item?.id, item?.label);
                onChanged(item?.id);
              },
            ),
          ),
        );
      },
    );
  }
}
```

UnifiedFilterBar 의 `_resolvePaymentMethodName` 정적 헬퍼(line 402-409) 는 `onChangedWithName` 콜백으로 대체 — name 을 sheet 에서 직접 받아 정확성↑.

PocketFilter 도 동일하게 `ItemSelectorField` + `ItemSelectorSheet`(group/favoriteType 없음, icon `Icons.savings`).

## 성능 설계 (원칙 1.4)
- **데이터 접근**: 변경 없음. 기존 `PaymentMethodBloc`/`PocketBloc`/`CategoryBloc` 의 in-memory state 사용. 추가 API 호출 없음.
- **예상 규모**: 결제수단/포켓/카테고리는 사용자당 수십 개 이내 → 정렬·그룹화 O(N log N) 영향 무시 가능.
- **리소스 제약**: web 메모리에 영향 없음. 시트 sheet 1개당 widget tree 깊이 ~5 추가 — 기존 transaction_form_page 와 동일 패턴이므로 검증된 수준.
- **렌더링 비용**: `ItemSelectorSheet` 는 `ListView` + `BlocBuilder<FavoritesBloc>` — 이미 거래 폼에서 사용 중. 신규 비용 없음.
- **네트워크 절감**: 기간 즉시 적용 제거로 사용자가 여러 필터 조합 시 1회 요청만 발생 (기존엔 기간 1회 + 적용 1회 = 2회).

## 실패 발생 시 — §5.4 실패 처리 3 단계

### 1. 원인 분석
- **주요 원인**: `TotalAssetMiniCard` 가 `BlocBuilder<PaymentMethodBloc>` 사용. `/transactions` 라우트의 `MultiBlocProvider` 에는 `TransactionBloc` / `TransferBloc` 만 공급되어 있음. `PaymentMethodBloc` 은 getIt 싱글턴으로만 존재, BlocProvider 트리에는 없음 → `ProviderNotFoundException` → `_buildLoaded` Column 전체 렌더 실패.
- **AppBar 카운트는 왜 보였나**: AppBar 는 Builder 로 `context.watch<TransactionBloc>` 사용, `_buildLoaded` 와 별도 스코프. Exception 이 body 만 영향.
- **기획 검증 누락 지점**: 기획서에 "context.read 가능 여부 확인 필요" 라고 **적기만 하고 실제 확인 안 함**. 코드 확인 시 line 274 에서 `getIt<PaymentMethodBloc>().state` 로 state 를 직접 읽는 패턴을 봤으나, 이것이 "Provider 가 공급되어 있다"는 증거가 아님을 놓침. 원칙 1.2 (정확성 우선) 위반.
- **Phase 25 점진 이행 원칙은 지켜졌나**: Zero regression 실패. "추가만" 이라도 추가된 위젯이 런타임 의존성을 만들면 회귀 발생 가능함을 과소평가.

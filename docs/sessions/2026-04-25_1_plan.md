### C. 한글 폰트 9초 로딩 해결 (P-6)
- **원인 추정**:
  - `aiva-bb.conf` gzip_types 에 `font/ttf` 있음. 하지만 **매 요청마다 실시간 gzip 인코딩** 발생 (gzip_comp_level 6) → NAS 저사양 CPU 로 느림
  - `/assets/fonts/` 위치에 **Cache-Control 미설정** → 재방문 시도 매번 다운로드 가능
  - NotoSansKR Variable Font 2.2MB 원본
- **변경**: `ops/nas-nginx/aiva-bb.conf`
  - `/assets/fonts/` exact prefix 에 long-term cache 추가:
    ```
    location ^~ /assets/fonts/ {
        add_header Cache-Control "public, max-age=31536000, immutable" always;
        try_files $uri =404;
    }
    ```
  - `gzip_comp_level 6` → `gzip_comp_level 4` (NAS CPU 부담 경감, 크기 차이 미미)
  - `gzip_static on` 추가 고려 — 단 빌드 산출물에 `.gz` 파일 없으므로 no-op. 일단 skip.
- **기대 효과**: 재방문 시 304 → 즉시, 초기 방문도 comp_level 낮춤으로 NAS CPU 응답 빨라짐
- **회귀 위험**: 저. Cache-Control 은 static asset 에만 영향. 만약 폰트 교체 필요 시 `.ttf` 파일명 해시 변경하면 자동 cache bust.

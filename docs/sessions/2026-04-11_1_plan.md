## Part 1: AI 거래 자동 분류

### 아키텍처: 패턴매칭 우선 + Claude Haiku fallback + Redis 캐싱

```
[FE] description 입력 (debounce 500ms)
  → [BE] POST /api/v1/ai/classify
    → 1차: Redis 캐시 확인 (couple:{id}:classify:{hash})
    → 2차: 기존 getSuggestions() 패턴매칭 (DB 기반)
    → 3차: Claude Haiku API 호출 → 결과 Redis 캐시 (TTL 30일)
    → 응답: { categoryId, categoryName, groupName, confidence, source }
```

### BE 구현

#### 신규 패키지: `com.budgetbook.ai`
```
ai/
├── config/ClaudeApiConfig.kt         — API key, 모델, timeout
├── controller/AiController.kt        — /api/v1/ai/classify, /api/v1/ai/insights
├── service/AiClassificationService.kt — 분류 (패턴→캐시→AI)
├── service/AiInsightService.kt       — 인사이트 생성
├── service/ClaudeApiClient.kt        — Claude API HTTP 클라이언트 (WebClient)
└── dto/AiDtos.kt                     — Request/Response DTOs
```

#### 환경변수
```
ANTHROPIC_API_KEY=sk-ant-...
AI_ENABLED=true
```

#### 모델: Claude Haiku 4.5
- 분류 작업에 충분한 성능, 최저 비용
- 월 $0.02 미만 (캐싱 후 API 호출 30% 이하)

### FE 구현
- 거래 입력 폼: description 입력 완료 시 분류 API 호출
- 기존 suggestion 옆에 "AI 추천" 뱃지로 표시
- 사용자가 탭하여 수락 또는 무시
- AI 실패 시 기존 패턴매칭만 표시 (graceful degradation)

## Part 2: AI 소비 인사이트

### 아키텍처: 온디맨드 생성 + Redis 캐싱

```
[FE] "AI 인사이트" 버튼/카드
  → [BE] GET /api/v1/ai/insights?year=2026&month=4
    → Redis 캐시 확인 (TTL 7일)
    → 캐시 없으면: 통계 수집 → Claude Sonnet 호출 → 캐시 저장
    → 응답: { insights: [...], generatedAt }
```

### 인사이트 유형
| type | 예시 |
|------|------|
| SPENDING_CHANGE | "식비가 전월 대비 30% 증가. 외식비가 주요 원인" |
| BUDGET_WARNING | "교통비 예산 대비 초과 지출 잦음" |
| PATTERN | "주말 지출이 평일 대비 2배" |
| TIP | "카페 지출 줄이면 월 3만원 절약 가능" |
| POSITIVE | "저축률이 3개월 연속 상승 중!" |

### 모델: Claude Sonnet 4.6
- 분석 품질 중요 → Sonnet 사용
- 월 2-4회 호출 → 월 $0.02 미만

### FE 구현
- 리포트 페이지에 "AI 인사이트" 섹션 추가
- 인사이트 카드: severity별 아이콘/색상 (INFO=파랑, WARNING=주황, POSITIVE=녹색)
- 최초 생성 시 로딩 표시 (3-5초)
- 홈 대시보드에 최신 인사이트 1건 프리뷰

## Part 3: Rate Limiting 확장

### 현재 상태
- 2/24 엔드포인트만 적용 (AuthController, CoupleController)
- 수동 `rateLimiter.tryAcquire()` 방식

### 수정: AOP 어노테이션 기반으로 전환
```kotlin
@RateLimit(maxRequests = 30, windowSeconds = 60)
@PostMapping
fun createTransaction(...)
```

### 적용 대상
| 엔드포인트 | 제한 |
|-----------|------|
| POST /transactions | 30/분 |
| POST /transfers | 20/분 |
| POST /budgets | 20/분 |
| POST /categories | 20/분 |
| POST /ai/classify | 10/분 |
| GET /ai/insights | 2/시간 |
| POST /feedback | 5/분 |
| 기타 POST/PUT/DELETE | 30/분 |
| GET (목록 조회) | 60/분 |

## 성능 설계

| 항목 | 설계 |
|------|------|
| 분류 응답시간 | 캐시 hit <50ms, AI fallback 1-2초 |
| 인사이트 응답시간 | 캐시 hit <100ms, 생성 3-5초 |
| API 비용 | 분류 ~$0.02/월 + 인사이트 ~$0.02/월 = **총 $0.04/월** |
| 캐시 전략 | 분류: Redis TTL 30일, 인사이트: Redis TTL 7일 |
| 에러 처리 | AI 장애 시 기존 기능 100% 동작 (graceful degradation) |
| NAS 제약 | 외부 API 호출만 추가, 메모리 영향 최소 |

## Part A: 이체 규칙 정리

### 허용/차단 매트릭스
| Source \ Dest | CASH | DEBIT | BANK | CREDIT |
|--------------|------|-------|------|--------|
| **CASH** | O (다른 수단만) | O | O | O |
| **DEBIT** | O | O (다른 수단만) | O | O |
| **BANK** | O | O | O (다른 수단만) | O |
| **CREDIT** | O | O | O | **X** |

**규칙**: `source.type == CREDIT && dest.type == CREDIT` 일 때만 차단. 나머지 전부 허용.
기존 `source != dest` 체크에 추가.

## Part B: 잔고/정산 고도화

### B1. 은행/현금/체크카드 잔고 (실시간 계산)

**잔고 공식**:
```
balance = SUM(INCOME) - SUM(EXPENSE) + SUM(transfer_in) - SUM(transfer_out)
```

**BE 구현**: 단일 벌크 쿼리로 커플 전체 결제수단 잔고를 한 번에 계산 (N+1 방지)

```sql
-- 거래 기반 순잔고 (전체 결제수단, 한 번에)
SELECT t.payment_method_id,
  COALESCE(SUM(CASE WHEN t.type='INCOME' THEN t.amount ELSE 0 END), 0) -
  COALESCE(SUM(CASE WHEN t.type='EXPENSE' THEN t.amount ELSE 0 END), 0) AS net
FROM transactions t
WHERE t.couple_id = :coupleId AND t.payment_method_id IS NOT NULL
GROUP BY t.payment_method_id

-- 이체 입금 합계 (전체 결제수단, 한 번에)
SELECT tr.destination_payment_method_id, COALESCE(SUM(tr.amount), 0)
FROM transfers tr WHERE tr.couple_id = :coupleId
GROUP BY tr.destination_payment_method_id

-- 이체 출금 합계 (전체 결제수단, 한 번에)
SELECT tr.source_payment_method_id, COALESCE(SUM(tr.amount), 0)
FROM transfers tr WHERE tr.couple_id = :coupleId
GROUP BY tr.source_payment_method_id
```

**API 응답 확장**: 기존 `GET /api/v1/payment-methods` 응답에 `balance: Long?` 추가
- CASH/DEBIT/BANK: 잔고 값 반환
- CREDIT: null (정산 금액은 별도 API)

**추후 성능 최적화 (이번 범위 밖, 설계만 기록)**:
- 월별 스냅샷 테이블 (`payment_method_balance_snapshots`)
- 스케줄러가 매월 1일 전월 말 잔고를 스냅샷 저장
- 잔고 = 최근 스냅샷 + 이후 거래/이체 실시간 집계
- 스냅샷 이전 데이터는 쿼리하지 않아 속도 향상

## Part D: 실시간 동기화 (WebSocket) 활성화

### 현재 상태
- **BE**: WebSocket 설정, STOMP, JWT 인증, SyncEventPublisher 모두 구현 완료
- **FE**: WebSocketService, WebSocketBloc, SyncEventHandler 모두 구현 완료
- **문제**: `WebSocketConnect` 이벤트가 **어디에서도 호출되지 않음** → 항상 "오프라인"

### 수정 내용

#### D1. WebSocket 연결 트리거 (핵심 수정)
`main_shell_page.dart`에 `BlocListener<AuthBloc>` 추가:
```dart
BlocListener<AuthBloc, AuthState>(
  listener: (context, state) {
    if (state is AuthAuthenticated && state.user.coupleId != null) {
      context.read<WebSocketBloc>().add(WebSocketConnect(
        baseUrl: ApiEndpoints.baseUrl,
        accessToken: state.accessToken,
        coupleId: state.user.coupleId!,
        currentUserId: state.user.id,
      ));
    } else {
      context.read<WebSocketBloc>().add(WebSocketDisconnect());
    }
  },
)
```

#### D2. Transfer 동기화 이벤트 추가
- BE `TransferService`: TRANSFER_CREATED, TRANSFER_UPDATED, TRANSFER_DELETED 이벤트 발행 (이미 구현됨)
- FE `SyncEventHandler`: TRANSFER 이벤트 핸들링 추가
  ```dart
  case 'TRANSFER':
    _refreshTransfers();
    _refreshPaymentMethods(); // 잔고 갱신
    _refreshDashboard();
  ```

#### D3. 잔고 실시간 갱신
거래/이체 변경 시 결제수단 목록도 리프레시 (잔고 재계산):
```dart
// SyncEventHandler 수정
case 'TRANSACTION':
  _refreshTransactions();
  _refreshPaymentMethods(); // 잔고 영향
  _refreshDashboard();
```

#### D4. 연결 상태별 UI 개선
- 연결됨: 배너 숨김 (현재 동작)
- 재연결 중: 주황 "연결 중..." (현재 동작)
- 연결 끊김: 빨간 배너 + "재연결" 버튼 추가

## 성능 설계
- **잔고 벌크 쿼리**: 커플 전체 결제수단을 3개 쿼리로 한 번에 집계 (N+1 방지)
  - 거래 순잔고: GROUP BY payment_method_id (1 쿼리)
  - 이체 입금: GROUP BY destination_payment_method_id (1 쿼리)
  - 이체 출금: GROUP BY source_payment_method_id (1 쿼리)
  - 총 3 쿼리로 모든 결제수단 잔고 계산
- **추후 하이브리드 최적화**: 월별 스냅샷 + 이후 실시간 집계 (데이터 증가 시)
- **정산 금액**: 기존 쿼리 재활용 (2번 호출: 전월+이번달)
- **자동결제 스케줄러**: 매일 1회, 카드 수 소규모 → 성능 무관
- **WebSocket**: 기존 exponential backoff 재연결 전략 유지 (1s~30s)
- **동기화 최적화**: self-authored 이벤트 필터링으로 중복 리프레시 방지

## 보안 설계
| 항목 | 대응 |
|------|------|
| linkedBankId IDOR | 같은 커플 소속 + type=BANK 검증 |
| 이체 CREDIT↔CREDIT | 서비스 레이어 + DB CHECK 없음 (서비스만으로 충분) |
| 시스템 계정 보호 | FE 사용자 목록에서 제외, login 불가, author 변경만 허용 |
| 자동결제 중복 | auto_settlement_key UNIQUE 제약 |
| WebSocket JWT | 기존 handshake 인증 유지 |
| WebSocket topic | coupleId 소속 검증 (기존 구현) |
| 잔고 visibility | SHARED + 요청자 PRIVATE 거래만 집계 |

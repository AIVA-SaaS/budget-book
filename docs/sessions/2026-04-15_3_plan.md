# Phase 20-C: 카드 결제 데이터 모델 구조 개선 — 결제 완료 상태 + 이중 계산 방지
> 날짜: 2026-04-15 | 회차: 3 | 상태: 승인

## 요청 내용
1. **결제 후에도 미결제 금액에 계속 나옴** — 결제가 원본 거래를 "결제 완료" 처리하지 않음
2. **결제 이체가 은행 사용량에 이중 계산** — 카드 원본 거래 + 은행→카드 이체 = 2중 지출

## 하네스 Scope Audit 결과 (Step 1.5)
- **실행**: `recurrence_check.py . "amount_calculation,db_schema"`
- **amount_calculation**: 🚫 STRUCTURAL_FIX_REQUIRED (5회째)
- **필수 조치**: 패치 수정 불허 — 구조적 수정 필수
- **구조적 수정 계획**: 데이터 모델에 결제 완료 상태 추가 + 이체 플래그로 이중 계산 방지

## 근본 원인 분석

### Issue 1: 결제 완료 상태 누락
- `Transaction` 엔티티에 `paidAt` 필드 없음
- `Transfer` 엔티티에 `is_card_settlement` 플래그 없음
- 결제 이체 생성 시 원본 거래를 "결제 완료"로 표시하지 않음
- → unpaidMonth 조회 시 이미 결제된 거래도 포함됨

### Issue 2: 이체 이중 계산
- 카드 원본 거래: 50,000 EXPENSE
- 결제 이체 (은행→카드): 50,000
- `StatisticsService`가 모든 transferOut을 지출에 합산 → 은행 지출 50,000으로 계산
- 카드 지출도 50,000으로 계산 → **총 지출 100,000 (실제 50,000)**

## 구조적 수정 계획

### 1. 데이터 모델 변경
**Transaction 엔티티**:
- `paidAt: LocalDate?` 추가 — 결제 완료된 날짜 (null = 미결제)

**Transfer 엔티티**:
- `isCardSettlement: Boolean` 추가 (default false) — 카드 결제 이체 여부

### 2. Flyway 마이그레이션
- `V46__add_paid_at_to_transactions.sql`
- `V47__add_is_card_settlement_to_transfers.sql`

### 3. 결제 API (신규)
신규 엔드포인트: `POST /api/v1/card-settlements`
- Request: `sourcePaymentMethodId`, `destinationPaymentMethodId`, `amount`, `date`, `transactionIds[]`, `transferIds[]`
- 처리:
  1. Transfer 생성 (`is_card_settlement = true`)
  2. `transactionIds`의 각 Transaction에 `paid_at = transferDate` 설정
  3. `transferIds`의 각 Transfer는... Transfer는 "결제" 개념이 없으므로 별도 처리 (일단 Transfer 선택 비포함, 향후 확장)

### 4. 조회 로직 수정
**unpaidMonth** (`PaymentMethodService.buildMonthBySettlementDate`):
- Transaction: `WHERE paid_at IS NULL` 필터 추가
- Transfer OUT: `WHERE is_card_settlement = false` 필터 (카드 결제 이체는 미결제 대상에서 제외)

**getSettlementTransactions**:
- Transaction: `WHERE paid_at IS NULL` 필터 추가
- Transfer: `WHERE is_card_settlement = false` 필터

### 5. 통계 로직 수정 (이중 계산 방지)
**모든 Transfer 집계 API에서 `is_card_settlement = true` 제외**:
- `StatisticsService.getMonthlySummary`
- `StatisticsService.getCategoryBreakdown` (이체 가상 카테고리)
- `StatisticsService.getMonthlyTrend`
- `StatisticsService.getPeriodSummary`
- `PaymentMethodStatisticsService.getPaymentMethodStats`
- `ReportService.getWeeklyReport`
- `PaymentMethodService.buildMonthByTransactionDate` (currentMonth/previousMonth)

**TransferRepository에 필터링 메서드 추가**:
- 기존 `sumAmountBySourceForCoupleAndPeriod` → `sumAmountBySourceForCoupleAndPeriodExcludingSettlement`
- 기존 메서드는 유지 (카드 결제 페이지처럼 결제 이체 포함 필요한 경우)

### 6. FE 반영
- `card_settlement_page.dart`: 선택된 transactionIds를 서버로 전송
- `card_settlement_bloc.dart`: 신규 API 사용
- 결제 완료 후 카드 결제 현황 BLoC 리로드

## 성능 설계
- 추가 컬럼 2개 (nullable) — 기존 데이터 영향 없음
- 인덱스: `transactions.paid_at` 부분 인덱스 (미결제 조회 가속)

- Transfer 필터링: 기존 쿼리와 동일 스키마, WHERE 1개 추가

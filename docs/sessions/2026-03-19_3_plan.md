# 개인화(Private Visibility) 전체 설계
> 날짜: 2026-03-19 | 회차: 3 | 상태: 기획 (다음 세션 진행 예정)

## 요청 내용
커플 공유 가계부 내에서 개인 전용 항목(용돈, 비상금 등)을 관리.
- 해당 항목의 거래/예산/카테고리는 본인만 볼 수 있음
- 단순히 카테고리뿐 아니라 **예산, 통계, 리포트, 내보내기, 실시간 동기화** 등 전체적으로 개인화 반영

---

## 핵심 개념: Visibility (`SHARED` / `PRIVATE`)

| 구분 | 보이는 사람 | 통계 포함 | 예시 |
|------|-----------|----------|------|
| `SHARED` (기본) | 커플 모두 | 커플 통계 | 식비, 교통비, 월세 |
| `PRIVATE` | 본인만 | 개인 통계만 | 용돈, 비상금, 개인 저축 |

-- ============================================
-- 1. transactions: visibility + owner_id 추가
-- ============================================
ALTER TABLE transactions
    ADD COLUMN visibility VARCHAR(10) NOT NULL DEFAULT 'SHARED',
    ADD COLUMN owner_id UUID REFERENCES users(id) ON DELETE SET NULL;

ALTER TABLE transactions
    ADD CONSTRAINT ck_transactions_visibility
    CHECK (visibility IN ('SHARED', 'PRIVATE'));

    CHECK (visibility = 'SHARED' OR owner_id IS NOT NULL);

## BE 공통 패턴: VisibilityFilter

모든 조회 쿼리에 동일 패턴 적용:

```kotlin
// 기존
WHERE t.couple.id = :coupleId

// 변경
WHERE t.couple.id = :coupleId
  AND (t.visibility = 'SHARED' OR t.owner.id = :currentUserId)
```

### 집계 쿼리 분리 패턴

```kotlin
// 커플 통계 (대시보드, 공유 리포트)
WHERE couple_id = :coupleId AND visibility = 'SHARED'

// 개인 통계 (내 개인 탭)
WHERE couple_id = :coupleId AND visibility = 'PRIVATE' AND owner_id = :userId

// 전체 통계 (본인 기준 모든 것)
WHERE couple_id = :coupleId
  AND (visibility = 'SHARED' OR owner_id = :userId)
```

## WebSocket 개인화

```kotlin
// SyncEventPublisher 변경
fun publish(event: SyncEvent) {
    if (event.visibility == "PRIVATE") {
        // 특정 사용자에게만 전송
        messagingTemplate.convertAndSendToUser(
            event.ownerId, "/queue/private", event
        )
    } else {
        // 기존: 커플 채널 브로드캐스트
        messagingTemplate.convertAndSend(
            "/topic/couple/${event.coupleId}", event
        )
    }
}
```

FE: `/queue/private` 구독 추가 → PRIVATE 데이터 변경 실시간 수신

## 보안 설계

| 위협 | 대응 |
|------|------|
| API 응답에 상대방 PRIVATE 노출 | **서버 필터링** — 모든 조회 쿼리에 visibility 조건 |
| PRIVATE 거래 ID 직접 접근 | **소유권 검증** — owner_id == currentUser 확인 |
| 통계에 PRIVATE 데이터 누출 | **집계 쿼리 분리** — SHARED/PRIVATE 별도 합산 |
| WebSocket으로 PRIVATE 이벤트 수신 | **채널 분리** — PRIVATE는 /queue/private로 전송 |
| CSV 내보내기에 PRIVATE 포함 | **visibility 필터** 파라미터 적용 |
| 상대방이 개인 카테고리/예산 수정 | **owner_id 검증** — PRIVATE 엔티티는 owner만 수정/삭제 |

## 성능 설계
- **쿼리 영향**: 모든 couple 조회에 `AND (visibility = 'SHARED' OR owner_id = :userId)` 추가
  - `idx_transactions_visibility_owner` 복합 인덱스로 커버
  - SHARED가 대다수 → 인덱스 선택도 높음
- **데이터 규모**: 개인 거래는 전체의 5~10% 예상 → 증가량 미미
- **WebSocket**: owner 필터링은 인메모리 비교 — 추가 DB 조회 없음
- **통계 쿼리**: visibility 조건 추가로 인덱스 스캔 범위 오히려 줄어듦

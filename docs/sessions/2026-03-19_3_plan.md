# 개인 항목 (용돈/비상금) 기능
> 날짜: 2026-03-19 | 회차: 3 | 상태: 기획 (다음 세션 진행 예정)

## 요청 내용
커플 공유 가계부 내에서 개인 전용 항목(용돈, 비상금 등)을 관리할 수 있어야 한다.
- 매달 일정 금액이 입금되는 개인 예산
- 해당 항목의 거래 내역은 본인만 볼 수 있음 (상대방에게 숨김)
- 개인이 자유롭게 사용/기록

## 현재 구조 분석
- 모든 데이터: `couple_id` 기준 공유 → 커플 양쪽 모두 조회 가능
- 거래, 카테고리, 예산, 결제수단 전부 커플 공유
- 거래에 `owner_id` 없음 — 누가 기록했는지만 `created_by`로 추적
- 통계/요약도 커플 전체 기준

## 설계

### 핵심 개념: 거래 공개 범위 (visibility)

| 구분 | visibility | 보이는 사람 | 통계 포함 | 예시 |
|------|-----------|-----------|----------|------|
| 공유 (기본) | `SHARED` | 커플 모두 | 커플 통계 | 식비, 교통비 |
| 개인 | `PRIVATE` | 본인만 | 개인 통계만 | 용돈, 비상금 |

### DB 변경

#### 1. transactions 테이블
```sql
ALTER TABLE transactions
    ADD COLUMN visibility VARCHAR(10) NOT NULL DEFAULT 'SHARED',
    ADD COLUMN owner_id UUID REFERENCES users(id) ON DELETE SET NULL;

ALTER TABLE transactions
    ADD CONSTRAINT ck_transactions_visibility
    CHECK (visibility IN ('SHARED', 'PRIVATE'));

-- PRIVATE 거래는 반드시 owner_id가 있어야 함
ALTER TABLE transactions
    ADD CONSTRAINT ck_private_requires_owner
    CHECK (visibility = 'SHARED' OR owner_id IS NOT NULL);

CREATE INDEX idx_transactions_owner_visibility
    ON transactions (owner_id, visibility);
```

#### 2. categories 테이블
```sql
ALTER TABLE categories
    ADD COLUMN visibility VARCHAR(10) NOT NULL DEFAULT 'SHARED',
    ADD COLUMN owner_id UUID REFERENCES users(id) ON DELETE SET NULL;

ALTER TABLE categories
    ADD CONSTRAINT ck_categories_visibility
    CHECK (visibility IN ('SHARED', 'PRIVATE'));

ALTER TABLE categories
    ADD CONSTRAINT ck_private_category_requires_owner
    CHECK (visibility = 'SHARED' OR owner_id IS NOT NULL);
```

#### 3. monthly_budgets 테이블
```sql
ALTER TABLE monthly_budgets
    ADD COLUMN visibility VARCHAR(10) NOT NULL DEFAULT 'SHARED',
    ADD COLUMN owner_id UUID REFERENCES users(id) ON DELETE SET NULL;
```

### BE 변경

#### 거래 조회 로직 변경
```
기존: WHERE couple_id = :coupleId
변경: WHERE couple_id = :coupleId
      AND (visibility = 'SHARED' OR owner_id = :currentUserId)
```

모든 거래 관련 쿼리(목록, 검색, 통계, 합산)에 이 필터 적용.

#### 카테고리 조회 로직 변경
```
기존: WHERE couple_id = :coupleId
변경: WHERE couple_id = :coupleId
      AND (visibility = 'SHARED' OR owner_id = :currentUserId)
```

#### 개인 거래 생성
- `CreateTransactionRequest`에 `visibility: String?` (default: "SHARED") 추가
- `visibility = PRIVATE`이면 `owner_id`를 현재 사용자로 자동 설정
- 개인 카테고리에 거래 생성 시 자동으로 `PRIVATE` 설정

#### 개인 카테고리 생성
- `CreateCategoryRequest`에 `visibility: String?` 추가
- 기본 개인 카테고리 시딩: "용돈", "비상금" (각 사용자별)

#### 통계 분리
- 커플 통계: `visibility = 'SHARED'`만 포함
- 개인 통계: 별도 엔드포인트 또는 쿼리 파라미터 `?visibility=PRIVATE`
- 대시보드: 공유 요약 + 개인 요약 분리 표시

### FE 변경

#### 카테고리 선택
- `HierarchicalSelectorSheet`에 개인 카테고리 섹션 추가
- 시각 구분: 잠금 아이콘 🔒 또는 "개인" 뱃지
- 개인 카테고리 선택 시 거래 자동 PRIVATE 설정

#### 거래 목록
- 개인 거래: 잠금 아이콘 표시
- 상대방의 PRIVATE 거래는 API 응답에 포함되지 않음 (서버 필터링)

#### 예산
- 개인 예산: "내 용돈 20만원" — 본인만 진행률 확인
- 공유 예산과 별도 섹션으로 표시

#### 대시보드
- 공유 지출 요약 (기존)
- + 내 개인 지출 요약 (새로 추가)

### 반복 입금 (매달 용돈)
- 기존 `recurring_transactions` 활용
- `visibility: PRIVATE`, `type: INCOME`, `amount: 200000`, `interval: MONTHLY`
- 매달 자동 생성되는 개인 수입 거래

### WebSocket 동기화
- `PRIVATE` 거래의 CRUD 이벤트는 `owner_id` 사용자에게만 전송
- `SHARED` 거래는 기존대로 커플 채널로 전송

## 성능 설계
- **쿼리 영향**: 모든 거래/카테고리 쿼리에 `AND (visibility = 'SHARED' OR owner_id = :userId)` 추가
  - `idx_transactions_owner_visibility` 인덱스로 커버
  - 기존 쿼리 대비 미미한 오버헤드 (인덱스 스캔)
- **데이터 규모**: 개인 거래는 전체의 소수 (용돈/비상금 위주) → 증가량 미미
- **WebSocket**: owner 필터링은 서버 메모리 내 비교 — 추가 DB 조회 없음

## 보안 고려사항
- **서버 필터링 필수**: 클라이언트 숨김이 아닌 API 응답 단계에서 PRIVATE 거래 제외
- **소유권 검증**: PRIVATE 거래 수정/삭제는 owner_id == 현재 사용자만 허용
- **통계 누출 방지**: 커플 통계에 PRIVATE 거래 포함 금지

## 검증 계획
- [ ] PRIVATE 거래: 생성 → 본인 조회 가능, 상대방 조회 불가
- [ ] PRIVATE 카테고리: 본인만 보임
- [ ] 커플 통계: PRIVATE 제외 확인
- [ ] 개인 통계: PRIVATE만 포함 확인
- [ ] WebSocket: PRIVATE 이벤트 상대방 미수신 확인
- [ ] 반복 거래: PRIVATE 반복 → 매달 PRIVATE 거래 자동 생성

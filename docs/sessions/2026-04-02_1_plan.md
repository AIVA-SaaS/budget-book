# 기능 장애 종합 수정 + 데이터 흐름 고도화
> 날짜: 2026-04-02 | 회차: 1 | 상태: 기획

## 요청 내용
사용자가 보고한 9건의 기능 장애 + 관련 영역 전수 점검 + 고도화 제안

---

## 근본 원인 분석

### 핵심 아키텍처 문제: **월 컨텍스트(Year/Month) 전파 부재**

현재 앱에서 여러 화면 간 이동 시 **선택된 월 정보가 전달되지 않고 `DateTime.now()`로 초기화**되는 구조적 문제가 있음. 이것이 보고된 장애 9건 중 5건의 근본 원인.

```
[통계: 3월 선택] → 결제수단 클릭 → [거래 내역: DateTime.now() = 4월] ← 버그
[지출계획: 3월] → 뒤로가기 → [지출계획: 상태 유실] ← 버그
[홈 대시보드] → 4월 거래 없음 → [결제수단 위젯 미표시] ← 버그
```

---

## 장애 항목별 분석

### BUG-1: 통계 > 결제수단 클릭 시 현재 월로 이동 (심각도: High)

**증상**: 3월 통계에서 결제수단 클릭 → 거래 내역이 4월로 표시
**근본 원인**: `payment_method_stats_tab.dart:125`에서 년/월 파라미터 미전달
- `context.push('/transactions?paymentMethodId=X')` — year/month 없음
- `app_router.dart:253-267`에서 `DateTime.now()` 하드코딩
- `transaction_list_page.dart` 생성자에 year/month 파라미터 없음

**영향 범위** (조사 결과 추가 발견):
- 통계 > 카테고리별 클릭 시에도 동일 문제 예상
- 예산 > 카테고리 클릭 → 거래 내역 이동 시에도 동일 가능
- 리포트 > 상세 이동 시에도 동일 가능
- **전체 앱에서 `/transactions` 라우트로 이동하는 모든 곳 점검 필요**

**수정**:
1. `/transactions` 라우트에 `year`, `month` 쿼리 파라미터 추가
2. `app_router.dart`에서 파라미터 추출 → BLoC 전달
3. 모든 `context.push('/transactions?...')` 호출부에 year/month 추가

---

### BUG-2: 거래 내역 페이지네이션 시 금액 변동 (심각도: High)

**증상**: 추가 데이터 로드 시 사용액/누적액이 달라짐
**근본 원인 2가지**:

**(a) 서버 총액 유실**: `transaction_bloc.dart:206-218`
- `LoadMoreTransactions` 시 `serverTotalIncome/serverTotalExpense`를 새 state에 전달하지 않음
- getter가 로드된 일부 거래만으로 재계산 → 금액 변동

**(b) 누적액 전체 재계산**: `transaction_list_page.dart:565-578`
- running total이 현재 로드된 전체 거래 기준으로 매번 재계산
- 추가 데이터 로드 시 이전 거래의 누적값도 전부 변경

**수정**:
1. `LoadMoreTransactions` 시 `serverTotalIncome/serverTotalExpense` 보존
2. 누적액은 서버에서 계산하거나, 페이지 단위가 아닌 전체 기준 유지

---

### BUG-3: 거래 입력 후 결제수단 금액 미갱신 (심각도: Medium)

**증상**: 새 거래 입력 후 결제수단별 목록에서 이전 금액 표시
**근본 원인**: `transaction_bloc.dart:235-262`
- 거래 생성 후 `TransactionBloc`만 새로고침
- `PaymentMethodBloc.cardSettlementSummary` 미갱신
- `DashboardBloc` 미갱신
- `StatisticsBloc` 미갱신

**영향 범위**: 거래 수정/삭제 시에도 동일

**수정**:
1. 거래 CUD 후 관련 BLoC 연쇄 갱신 (PaymentMethod, Dashboard, Statistics)

---

### BUG-4: 홈 탭 결제수단 위젯 미표시 (심각도: Medium)

**증상**: 4월에 거래 없으면 홈에서 결제수단별 지출 미표시
**근본 원인**: `dashboard_page.dart` 위젯이 데이터 없으면 아예 렌더링하지 않음

**수정**:
1. 데이터 없을 때 "이번 달 거래가 없습니다" 빈 상태 표시

**추가 제안**: 결제수단별 위젯에 지난달 비교 표시 ("지난달 대비 -30%")

---

### BUG-5: 지출계획 뒤로가기 시 항목 미표시 (심각도: Medium)

**증상**: 3월로 이동 → 뒤로가기 → 항목 사라짐
**근본 원인**: `spending_plan_bloc.dart:37`
- 월 변경 시 `emit(SpendingPlanLoading())` → 이전 데이터 즉시 제거
- 뒤로가기 시 이전 상태 복원 로직 없음

**수정**:
1. 로딩 시 이전 데이터 보존 (optimistic UI)
2. 또는 뒤로가기 시 현재 월 데이터 재로드

---

### BUG-6: 지출계획 완료 시 거래 날짜 미반영 (심각도: High)

**증상**: 완료 처리 시 선택한 날짜로 거래가 등록 안됨
**근본 원인**: 조사 결과 코드 자체는 정상 — `transactionDate`가 DTO→Service→Transaction에 전달됨
- `complete_plan_dialog.dart:135` — 날짜 포맷 정상
- `SpendingPlanService.kt:376` — `transactionDate = request.transactionDate` 정상

**의심 지점**:
- JSON 직렬화 시 날짜 포맷 불일치 가능 (FE: `yyyy-MM-dd` string → BE: `LocalDate`)
- 또는 기본값 `LocalDate.now()`가 사용되는 경로 존재 가능

**수정**:
1. BE 서비스에서 실제 저장되는 transactionDate 로깅 추가
2. FE에서 전송하는 request body 확인
3. 실제 테스트로 검증

---

### BUG-7: 이체 등록 불가 (심각도: Critical)

**증상**: 이체 등록 시 아무 반응 없음
**근본 원인**: `transfer_form_page.dart:131`
- `if (amount == null || amount <= 0) return;` — **사용자에게 에러 피드백 없이 조용히 실패**
- BE: `@field:Min(1)` 검증으로 0원 이체도 거부
- 금액 입력 또는 파싱에 문제가 있으면 사용자는 아무 피드백 없이 멈춤

**수정**:
1. 폼 검증 실패 시 에러 메시지 표시
2. BE 응답 에러도 사용자에게 표시
3. 실제 이체 API 호출이 되는지 네트워크 로그 확인

---

### BUG-8: 0원 거래 등록 불가 (심각도: Medium)

**증상**: 기록용 0원 거래를 만들 수 없음
**근본 원인**:
- FE: `transaction_form_page.dart:501` — `amount <= 0` 차단
- BE: `TransactionDtos.kt:54` — `@field:Min(1)` (최소 1원)
- BE: `TransferDtos.kt:24` — `@field:Min(1)`

**수정**:
1. FE: `amount < 0` 으로 변경 (0 허용)
2. BE: `@field:Min(0)` 으로 변경
3. 이체는 0원 불허 유지 (의미 없음)

---

### BUG-9: 총 지출 금액 깜빡임 (심각도: Medium)

**증상**: 페이지네이션 시 총 금액이 잠시 다른 값 표시 후 복원
**근본 원인**: BUG-2와 동일 — 서버 총액 유실 + 클라이언트 재계산
**수정**: BUG-2 수정에 포함

## 추가 제안 (기능 개선)

### 1. 글로벌 이벤트 버스 도입
현재 BLoC 간 연쇄 갱신이 `bloc.add(A); bloc.add(B);` 방식으로 산발적임.
**제안**: `SyncEventHandler` 또는 전용 이벤트 버스로 거래 CUD 이벤트를 브로드캐스트 → 각 BLoC이 구독.
이미 WebSocket `SyncEventHandler`가 있으므로 로컬 이벤트에도 확장 가능.

### 2. 빈 상태 디자인 통일
데이터 없는 화면에 일관된 빈 상태 위젯 (아이콘 + 안내 문구 + 액션 버튼).
홈 위젯, 거래 목록, 통계, 리포트 등 전체 적용.

### 3. 페이지네이션 개선
서버 응답에 `totalIncome`, `totalExpense`를 포함하여 클라이언트 재계산 의존도 제거.
현재도 서버 값이 있지만 LoadMore 시 유실됨 — 이 패턴을 표준화.

### 1. 주간 예산 일할 계산 → 월간 예산 사용 현황 반영
**문제**: `BudgetService.getBudgetSummary()` (Line 336)에서 `budget.amount`를 그대로 사용
- WEEKLY 예산의 경우 `weeklyAmount * daysInMonth / 7`로 환산해야 하나 미적용
- 예산 탭 월간 뷰의 예산 사용률이 부정확

**변경 파일**:
| 파일 | 변경 내용 |
|------|----------|
| `BudgetService.kt:336` | WEEKLY 예산의 effectiveBudgetAmount를 일할 계산으로 환산 |
| `BudgetDtos.kt` | 응답에 `budgetPeriod`, `weeklyAmount` 필드 포함 여부 확인 |

**로직**:
```kotlin
val effectiveBudgetAmount = if (budget.budgetPeriod == BudgetPeriod.WEEKLY) {
    val weeklyAmt = budget.weeklyAmount ?: (budget.amount * 7 / ym.lengthOfMonth())
    weeklyAmt * ym.lengthOfMonth() / 7  // 월간 환산
} else {
    budget.amount
}
```

### 2. 날짜 팝업 — 캘린더 뷰 단일 패널로 변경
**문제**: 웹(넓은 화면)에서 Flutter Material 3 DatePicker가 좌측 텍스트/편집 패널 + 우측 캘린더 패널 2개로 나뉘어 표시됨. 캘린더 뷰 1개만 있으면 충분.

**변경 파일**:
| 파일 | 변경 내용 |
|------|----------|
| `transaction_form_page.dart:850` | `initialEntryMode: DatePickerEntryMode.calendarOnly` 추가 |

`calendarOnly` 모드: 좌측 헤더 패널과 텍스트 입력 전환이 제거되고, 캘린더 뷰 단일 팝업만 표시. 기존 날짜 필드 클릭 → 캘린더 팝업 → 날짜 선택 플로우 유지.

### 4. 보험 기능 추가
**범위**: 보험은 "고정 지출"의 특수 유형으로, 정기적 보험료 납부를 관리하는 기능

**설계 방안 A — 별도 feature (추천)**:
- `insurance` feature: 보험 상품 CRUD (이름, 보험사, 보험료, 납부일, 납부주기, 결제수단, 시작일/만기일)
- 자동결제(auto_payment)와 연동: 보험료 자동 거래 생성
- 대시보드에 보험 요약 카드 (이번 달 보험료 총액, 다음 납부 예정)

**DB 테이블**: `insurances`
```sql
CREATE TABLE insurances (
  id UUID PRIMARY KEY,
  couple_id UUID NOT NULL REFERENCES couples(id),
  user_id UUID NOT NULL REFERENCES users(id),
  name VARCHAR(100) NOT NULL,          -- 보험 이름
  insurer VARCHAR(100),                 -- 보험사
  insurance_type VARCHAR(30) NOT NULL,  -- LIFE, HEALTH, CAR, FIRE, OTHER
  premium_amount BIGINT NOT NULL,       -- 보험료
  payment_day INT,                      -- 매월 납부일 (1-31)
  payment_cycle VARCHAR(20) DEFAULT 'MONTHLY', -- MONTHLY, QUARTERLY, YEARLY
  payment_method_id UUID REFERENCES payment_methods(id),
  category_id UUID REFERENCES categories(id), -- 연결 카테고리
  start_date DATE,                      -- 보험 시작일
  end_date DATE,                        -- 보험 만기일
  memo TEXT,
  is_active BOOLEAN DEFAULT TRUE,
  visibility VARCHAR(10) DEFAULT 'SHARED',
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

**API 엔드포인트**:
| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/v1/insurances` | 보험 목록 조회 |
| POST | `/api/v1/insurances` | 보험 등록 |
| PUT | `/api/v1/insurances/{id}` | 보험 수정 |
| DELETE | `/api/v1/insurances/{id}` | 보험 삭제 |
| GET | `/api/v1/insurances/summary` | 월별 보험료 요약 |

**FE 화면**:
- 보험 목록 페이지 (카드 형태, 보험사별 그룹)
- 보험 등록/수정 폼
- 홈 대시보드에 보험 요약 위젯

### 4. 카테고리/결제수단 선택 UI 개선

#### 4a. 속도 개선
**원인 분석**:
- CategoryGroupBloc이 매 열기 시 API 호출
- PaymentMethod도 캐시 미활용
- Bottom Sheet 열면서 로딩 스피너 표시

**해결**:
- 앱 시작 시 카테고리/결제수단 사전 로드 (DI 초기화 단계)

**현재**: Bottom Sheet (하단에서 올라옴)

## 성능 설계
- **주간 예산 계산**: 기존 쿼리 변경 없음, 서비스 레이어에서 산술 연산만 추가 (O(N), N=예산 개수)
- **보험 조회**: couple_id + is_active 인덱스, 페이징 불필요 (가구당 보험 10~20건)
- **카테고리 사전 로드**: 앱 시작 시 1회 호출, 이후 WebSocket invalidation 기반 갱신
- **즐겨찾기**: couple_preferences 단일 row 조회, UUID[] 필드 → 추가 쿼리 없음

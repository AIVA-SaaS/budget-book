# 영수증/알림 스크린샷 자동 인식 거래 입력
> 날짜: 2026-03-24 | 회차: 1 | 상태: 기획

## 요청 내용
영수증 사진이나 카드 앱 알림 스크린샷을 올리면 날짜, 항목, 금액, 결제수단이 자동 입력되는 기능

## 아키텍처

```
[Flutter 앱] 사진 촬영/갤러리
  │
  ▼
[BE API] POST /api/v1/transactions/scan
  │
  ├─ 1. 이미지 검증 (크기, 형식, 해상도)
  ├─ 2. OCR 텍스트 추출 (Google Vision / Tesseract)
  ├─ 3. OCR 품질 검증 (인식률 체크)
  ├─ 4. LLM 구조화 파싱 (Claude API Haiku)
  ├─ 5. 카테고리/결제수단 매칭 (사용자 데이터 기반)
  └─ 6. 응답 (확인 화면용 데이터)
        └─ 사용자 확인/수정 → 저장
```

## API 설계

### 요청
```
POST /api/v1/transactions/scan
Content-Type: multipart/form-data

image: (파일, 최대 10MB)
```

### 응답
```json
{
  "success": true,
  "data": {
    "confidence": 0.92,
    "date": "2026-03-24",
    "items": [
      {
        "description": "아메리카노",
        "amount": 4500,
        "suggestedCategoryId": "uuid",
        "suggestedCategoryName": "식비"
      }
    ],
    "totalAmount": 4500,
    "paymentMethod": "삼성카드",
    "suggestedPaymentMethodId": "uuid",
    "rawOcrText": "삼성카드 승인 4,500원 스타벅스...",
    "warnings": []
  }
}
```

### 에러 응답 (인식 실패)
```json
{
  "success": false,
  "error": {
    "code": "SCAN_FAILED",
    "message": "이미지에서 텍스트를 충분히 인식할 수 없습니다. 더 선명한 사진으로 다시 시도해주세요."
  }
}
```

## 방어 정책

### 1단계: 이미지 검증 (업로드 시)
| 검증 항목 | 기준 | 에러 메시지 |
|-----------|------|------------|
| 파일 크기 | 최대 10MB | "이미지 크기가 너무 큽니다 (최대 10MB)" |
| 파일 형식 | JPG, PNG, HEIC, WEBP | "지원하지 않는 이미지 형식입니다" |
| 최소 해상도 | 200x200px 이상 | "이미지가 너무 작습니다. 더 큰 이미지를 사용해주세요" |
| 최대 해상도 | 4096x4096px 이하 (초과 시 리사이즈) | 자동 리사이즈 |

### 2단계: OCR 품질 검증 (텍스트 추출 후)
| 검증 항목 | 기준 | 처리 |
|-----------|------|------|
| 추출 문자 수 | 10자 미만 | SCAN_FAILED: "텍스트를 인식할 수 없습니다. 글자가 선명한 사진으로 다시 시도해주세요" |
| 한글/숫자 비율 | 의미 있는 문자 30% 미만 | SCAN_FAILED: "이미지에서 거래 정보를 찾을 수 없습니다" |
| OCR 신뢰도 점수 | Google Vision confidence < 0.5 | SCAN_FAILED: "이미지가 흐리거나 손상되었습니다. 더 선명한 사진을 사용해주세요" |

### 3단계: LLM 파싱 검증 (구조화 후)
| 검증 항목 | 기준 | 처리 |
|-----------|------|------|
| 금액 추출 실패 | 금액 0원 또는 미추출 | warnings에 "금액을 정확히 인식하지 못했습니다" 추가, 사용자 수동 입력 유도 |
| 날짜 추출 실패 | 날짜 미추출 | 오늘 날짜로 기본값, warnings 추가 |
| 전체 신뢰도 | confidence < 0.6 | warnings에 "인식 정확도가 낮습니다. 결과를 확인해주세요" 추가 |
| 항목 0개 | LLM이 아무것도 추출 못함 | SCAN_FAILED: "거래 정보를 추출할 수 없습니다" |

### 4단계: 사용자 확인 (항상 필수)
- **자동 저장 절대 안 함** — 반드시 사용자 확인 화면 거침
- 신뢰도 90% 이상: 초록색 표시, "확인 후 저장"
- 신뢰도 60~90%: 노란색 표시, "인식 결과를 확인해주세요"
- 신뢰도 60% 미만: 빨간색 경고, "정확도가 낮습니다. 수동으로 수정해주세요"
- warnings가 있으면 해당 필드 옆에 경고 아이콘 표시

## 문제 대처

| 문제 | 대처 |
|------|------|
| 영수증 구겨짐/희미함 | Google Vision 전처리 + BE 이미지 보정 (대비, 샤프닝) |
| 앱 알림 형식 차이 (카드사별) | LLM 자연어 이해로 처리, 형식 무관 |
| 안드로이드/아이폰 차이 | 스크린샷 이미지이므로 OS 무관 |
| 여러 항목 영수증 (마트) | LLM에게 items[] 배열로 추출 요청 |
| 카테고리 매칭 | 사용자 기존 카테고리 목록을 LLM 프롬프트에 포함 |
| 결제수단 매칭 | 사용자 등록 결제수단 목록과 텍스트 유사도 매칭 |
| 개인정보 (카드번호 등) | OCR 텍스트에서 카드번호 마스킹 후 LLM 전달, 원본 저장 안 함 |

## LLM 프롬프트 설계

```
당신은 영수증/카드 알림 텍스트에서 거래 정보를 추출하는 파서입니다.

아래 OCR 텍스트에서 거래 정보를 추출하세요.

사용자의 카테고리: {categories}
사용자의 결제수단: {paymentMethods}

규칙:
- 날짜가 없으면 date를 null로
- 금액은 반드시 양수 정수 (원 단위)
- 여러 항목이면 items 배열에 모두 포함
- 카테고리는 사용자 목록에서 가장 적합한 것 선택
- 결제수단은 텍스트에서 카드사/은행명 매칭
- 확신도(confidence)를 0.0~1.0으로 평가

JSON으로만 응답:
{
  "confidence": 0.0~1.0,
  "date": "YYYY-MM-DD" | null,
  "items": [{"description": "...", "amount": 0, "suggestedCategory": "..."}],
  "totalAmount": 0,
  "paymentMethod": "..." | null
}

OCR 텍스트:
---
{ocrText}
---
```

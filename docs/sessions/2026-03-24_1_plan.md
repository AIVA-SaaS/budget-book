# 영수증/알림 스크린샷 자동 인식 거래 입력
> 날짜: 2026-03-24 | 회차: 1 | 상태: 기획

## 요청 내용
영수증 사진이나 카드 앱 알림 스크린샷을 올리면 날짜, 항목, 금액, 결제수단이 자동 입력되는 기능.
Tesseract 한글 인식률이 낮으므로 자체 한글/영수증 특화 OCR 모델도 검토.

---

## 아키텍처

```
[Flutter 앱] 사진 촬영/갤러리
  │
  ▼
[BE API] POST /api/v1/transactions/scan
  │
  ├─ 1. 이미지 검증 (크기, 형식, 해상도)
  ├─ 2. 이미지 전처리 (회전 보정, 대비 보정, 샤프닝)
  ├─ 3. OCR 텍스트 추출 (자체 모델 or PaddleOCR or Google Vision)
  ├─ 4. OCR 품질 검증 (인식률 체크)
  ├─ 5. LLM 구조화 파싱 (Claude API Haiku)
  ├─ 6. 카테고리/결제수단 매칭 (사용자 데이터 기반)
  └─ 7. 응답 (확인 화면용 데이터)
        └─ 사용자 확인/수정 → 저장
              └─ 수정 데이터 → 학습 데이터 자동 축적
```

## OCR 모델 전략 (3단계 로드맵)

### Phase 1: 기존 모델로 빠르게 시작
| 옵션 | 장점 | 단점 | NAS 배포 |
|------|------|------|----------|
| **PaddleOCR** (추천) | 한글 내장, 영수증 특화 모델 있음, 정확도 높음 | Python 런타임 필요 | Docker 컨테이너 |
| EasyOCR | 한글 내장, PyTorch 기반, 사용 간편 | PaddleOCR보다 느림 | Docker 컨테이너 |
| Google Cloud Vision | 최고 정확도, 전처리 내장 | 외부 API 의존, 비용 | API 호출 |

**결정**: NAS에 PaddleOCR Docker 컨테이너 배포. GPU 없어도 CPU 추론 가능 (1~3초/장).

```
NAS Docker 추가 구성:
├── ocr-service (PaddleOCR, Python Flask/FastAPI)
│   └── :5000 내부, budget-api에서 호출
└── 기존 서비스들...
```

### Phase 2: 사용자 교정 데이터 자동 축적
사용자가 인식 결과를 수정할 때마다 학습 데이터가 쌓임.

```
인식: "아메리카ノ 4,50O원"
수정: "아메리카노 4,500원"
저장: {
  image_id: "uuid",
  region: { x, y, w, h },        // 텍스트 영역 좌표
  ocr_result: "아메리카ノ",       // 모델 출력
  user_correction: "아메리카노",  // 정답
  created_at: "2026-04-01"
}
```

```sql
-- 학습 데이터 축적 테이블
CREATE TABLE ocr_training_data (
    id UUID PRIMARY KEY,
    couple_id UUID NOT NULL,
    original_image_path TEXT NOT NULL,     -- 원본 이미지 저장 경로
    image_region JSONB,                    -- 텍스트 영역 좌표 (optional)
    ocr_raw_text TEXT NOT NULL,            -- OCR 원본 출력
    user_corrected_text TEXT,              -- 사용자 수정 결과 (null = 수정 없음)
    field_type VARCHAR(20),               -- DESCRIPTION / AMOUNT / DATE / PAYMENT_METHOD
    confidence FLOAT,                      -- OCR 신뢰도
    created_at TIMESTAMP DEFAULT NOW()
);
```

**축적 조건**: 사용자가 인식 결과를 수정한 경우에만 저장 (수정 없이 저장 = 정답이므로 별도 저장 불필요... 하지만 정답 데이터도 가치 있으므로 옵션으로 저장)

### Phase 3: 자체 모델 파인튜닝
축적 데이터가 충분해지면 (1,000건+) 자체 모델 학습.

**베이스 모델 후보:**
| 모델 | 구조 | 파인튜닝 방식 | 필요 데이터 |
|------|------|-------------|------------|
| **PaddleOCR 인식기** | CRNN + CTC | 한국 영수증 데이터로 recognition 모델 파인튜닝 | 1,000~5,000건 |
| **TrOCR** (Microsoft) | Transformer encoder-decoder | 한글 영수증 텍스트 이미지 + 정답 쌍 | 3,000~10,000건 |
| **CRAFT + custom 인식기** | 검출(CRAFT) + 인식(custom) 분리 | 인식기만 파인튜닝 | 1,000~5,000건 |

**추천: PaddleOCR 파인튜닝** (이유: Phase 1에서 이미 사용 중이므로 전환 비용 0)

```
파인튜닝 파이프라인:
1. ocr_training_data 테이블에서 데이터 추출
2. PaddleOCR 학습 형식으로 변환 (이미지 + 라벨 txt)
3. Google Colab 또는 NAS(GPU 있을 경우)에서 학습
4. 학습된 모델을 ocr-service Docker에 교체 배포
5. 정확도 비교 (기존 vs 파인튜닝)
```

**학습 환경:**
| 환경 | 비용 | GPU | 학습 시간 (5,000건) |
|------|------|-----|-------------------|
| Google Colab (무료) | 무료 | T4 | 2~4시간 |
| Google Colab Pro | $10/월 | A100 | 30분~1시간 |
| NAS (GPU 없음) | 전기세 | CPU | 12~24시간 (비추) |
| NAS (GPU 추가 시) | 하드웨어 비용 | 추가 GPU | 1~3시간 |

## 방어 정책

### 1단계: 이미지 검증 (업로드 시)
| 검증 항목 | 기준 | 에러 메시지 |
|-----------|------|------------|
| 파일 크기 | 최대 10MB | "이미지 크기가 너무 큽니다 (최대 10MB)" |
| 파일 형식 | JPG, PNG, HEIC, WEBP | "지원하지 않는 이미지 형식입니다" |
| 최소 해상도 | 200x200px 이상 | "이미지가 너무 작습니다. 더 큰 이미지를 사용해주세요" |
| 최대 해상도 | 4096x4096px 이하 (초과 시 리사이즈) | 자동 리사이즈 |

### 2단계: OCR 품질 검증 (텍스트 추출 후)
| 검증 항목 | 기준 | 처리 |
|-----------|------|------|
| 추출 문자 수 | 10자 미만 | SCAN_FAILED: "텍스트를 인식할 수 없습니다. 글자가 선명한 사진으로 다시 시도해주세요" |
| 한글/숫자 비율 | 의미 있는 문자 30% 미만 | SCAN_FAILED: "이미지에서 거래 정보를 찾을 수 없습니다" |
| OCR 신뢰도 점수 | 평균 confidence < 0.4 | SCAN_FAILED: "이미지가 흐리거나 손상되었습니다. 더 선명한 사진을 사용해주세요" |
| 텍스트 영역 비율 | 이미지 대비 텍스트 영역 5% 미만 | SCAN_FAILED: "텍스트가 포함된 이미지를 사용해주세요" |

### 3단계: LLM 파싱 검증 (구조화 후)
| 검증 항목 | 기준 | 처리 |
|-----------|------|------|
| 금액 추출 실패 | 금액 0원 또는 미추출 | warnings: "금액을 정확히 인식하지 못했습니다" |
| 날짜 추출 실패 | 날짜 미추출 | 오늘 날짜 기본값 + warnings |
| 전체 신뢰도 | confidence < 0.6 | warnings: "인식 정확도가 낮습니다" |
| 항목 0개 | 추출 결과 없음 | SCAN_FAILED: "거래 정보를 추출할 수 없습니다" |
| 금액 비정상 | 1억 이상 또는 음수 | warnings: "금액이 정상 범위를 벗어납니다" |

### 4단계: 사용자 확인 (항상 필수)
- **자동 저장 절대 안 함** — 반드시 확인 화면 거침
- 신뢰도별 UI:
  - 90%+ : 초록색, "확인 후 저장"
  - 60~90%: 노란색, "인식 결과를 확인해주세요"
  - 60% 미만: 빨간색, "정확도가 낮습니다. 수동으로 수정해주세요"
- warnings 있는 필드 옆에 경고 아이콘 표시

## 문제 대처

| 문제 | 대처 |
|------|------|
| 영수증 구겨짐/희미함 | 이미지 전처리 (대비 보정, 샤프닝, 이진화) + OCR 모델이 못 읽으면 방어 정책 2단계에서 차단 |
| 앱 알림 형식 차이 (카드사별) | LLM이 자연어 이해로 처리 — 형식 무관 |
| 안드로이드/아이폰 차이 | 스크린샷 이미지이므로 OS 무관 |
| 여러 항목 영수증 (마트) | LLM에게 items[] 배열로 추출 요청 |
| 카테고리 매칭 | 사용자 기존 카테고리 목록을 LLM 프롬프트에 포함 |
| 결제수단 매칭 | 사용자 등록 결제수단 목록과 텍스트 유사도 매칭 |
| 개인정보 (카드번호 등) | OCR 텍스트에서 카드번호 마스킹 후 LLM 전달, 원본 이미지는 학습 데이터용으로만 보관 |
| 동일 영수증 중복 스캔 | 금액+날짜+내용 조합으로 중복 감지, warnings 표시 |

## LLM 프롬프트 설계

```
당신은 영수증/카드 알림 텍스트에서 거래 정보를 추출하는 파서입니다.

아래 OCR 텍스트에서 거래 정보를 추출하세요.

사용자의 카테고리: {categories}
사용자의 결제수단: {paymentMethods}

규칙:
- 날짜가 없으면 date를 null로
- 금액은 반드시 양수 정수 (원 단위)
- 여러 항목이면 items 배열에 모두 포함
- 카테고리는 사용자 목록에서 가장 적합한 것 선택
- 결제수단은 텍스트에서 카드사/은행명 매칭
- 확신도(confidence)를 0.0~1.0으로 평가
- 인식이 불확실한 글자는 가장 가능성 높은 해석 선택

JSON으로만 응답:
{
  "confidence": 0.0~1.0,
  "date": "YYYY-MM-DD" | null,
  "items": [{"description": "...", "amount": 0, "suggestedCategory": "..."}],
  "totalAmount": 0,
  "paymentMethod": "..." | null
}

OCR 텍스트:
---
{ocrText}
---
```

```dockerfile
# ocr/Dockerfile
FROM python:3.11-slim

RUN apt-get update && apt-get install -y libgl1-mesa-glx libglib2.0-0 && rm -rf /var/lib/apt/lists/*
RUN pip install paddlepaddle paddleocr fastapi uvicorn python-multipart Pillow

WORKDIR /app
COPY server.py .

# 한글 모델 사전 다운로드
RUN python -c "from paddleocr import PaddleOCR; PaddleOCR(lang='korean')"

EXPOSE 5000
CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "5000"]
```

```python
# ocr/server.py (간략)
from fastapi import FastAPI, UploadFile
from paddleocr import PaddleOCR
import io, json
from PIL import Image

app = FastAPI()
ocr = PaddleOCR(lang='korean', use_angle_cls=True)

@app.post("/ocr")
async def extract_text(image: UploadFile):
    img_bytes = await image.read()
    img = Image.open(io.BytesIO(img_bytes))
    result = ocr.ocr(img_bytes, cls=True)

    texts = []
    total_confidence = 0
    count = 0
    for line in result[0] or []:
        text, confidence = line[1]
        texts.append({"text": text, "confidence": confidence, "box": line[0]})
        total_confidence += confidence
        count += 1

    avg_confidence = total_confidence / count if count > 0 else 0

    return {
        "texts": texts,
        "fullText": " ".join(t["text"] for t in texts),
        "avgConfidence": avg_confidence,
        "charCount": sum(len(t["text"]) for t in texts)
    }
```

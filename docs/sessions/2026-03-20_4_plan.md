# 거래 계속 입력 + 동일 항목 유지 기능
> 날짜: 2026-03-20 | 회차: 4 | 상태: 기획

## 요청 내용
1. 거래 저장 후 "계속" 버튼으로 폼을 초기화하되, 선택한 날짜는 유지하여 연속 입력 가능
2. "동일 항목 유지" 토글로 날짜/카테고리/결제수단을 이전 입력과 동일하게 자동 세팅

## 현재 구현 상태
- 저장 버튼 클릭 → BLoC에서 CreateTransaction → 성공 시 이전 화면으로 pop
- 연속 입력 불가 — 매번 새 페이지로 진입해야 함
- 날짜/카테고리/결제수단을 매번 다시 선택해야 함

## 영향 범위 분석
- **변경 파일**: FE만 (BE 변경 불필요)

## 상세 설계

### 1. 하단 버튼 레이아웃 (새 거래 생성 시만)

```
┌─────────────────────────────────────────┐
│ [x] 동일 항목 유지 (날짜·카테고리·결제수단) │
├──────────────────┬──────────────────────┤
│   저장 & 계속     │       저장           │
│  (OutlinedButton) │   (FilledButton)     │
└──────────────────┴──────────────────────┘
```

- **저장**: 기존 동작 (저장 후 이전 화면으로 pop)
- **저장 & 계속**: 저장 후 폼 초기화, 현재 페이지 유지
- **동일 항목 유지**: 체크 시 "저장 & 계속" 동작 변경
- 수정 모드(isEditing)에서는 "저장" 버튼만 표시 (기존 동작)

### 2. "저장 & 계속" 동작

#### 체크 해제 (기본) — 날짜만 유지
```dart
void _onSubmitAndContinue() {
  _submitTransaction(continueMode: true);
}

void _resetFormForContinue() {
  setState(() {
    _amountController.clear();
    _amountHint = '';
    _descriptionController.clear();
    _memoController.clear();
    _isSubmitting = false;
    // 날짜는 유지 (_selectedDate 그대로)
    if (!_keepSameItems) {
      _selectedCategoryId = null;
      _selectedCategoryDisplayName = null;
      _selectedPaymentMethodId = null;
      _selectedPocketId = null;
      _loadDefaultPaymentMethod(); // 기본 결제수단 다시 로드
    }
    // 포켓은 항상 유지하지 않음 (선택적)
  });
  // 성공 피드백
  ScaffoldMessenger.of(context).showSnackBar(
    const SnackBar(
      content: Text('저장 완료! 다음 항목을 입력하세요.'),
      duration: Duration(seconds: 1),
    ),
  );
}
```

#### 체크 (동일 항목 유지) — 날짜 + 카테고리 + 결제수단 유지
```dart
// _keepSameItems = true 일 때:
// - _selectedDate 유지
// - _selectedCategoryId + _selectedCategoryDisplayName 유지
// - _selectedPaymentMethodId 유지
// - _selectedPocketId 유지
// - _selectedType 유지
// - 금액, 내용, 메모만 초기화
```

### 3. 상태 변수 추가

```dart
bool _keepSameItems = false;  // "동일 항목 유지" 체크 상태
```

### 4. BLoC 리스너 분기

현재 `TransactionBloc` 리스너에서 성공 시 `context.pop()`을 호출하는 부분을 수정:

```dart
// 현재: 저장 성공 → pop
// 변경: continueMode면 pop 대신 _resetFormForContinue 호출
```

실제로 현재 코드를 보면 `_onSubmit()`에서 BLoC 이벤트를 추가하고,
BLoC 내부에서 성공 시 `LoadTransactions`를 다시 호출합니다.
폼 페이지에서는 별도 성공 콜백이 없으므로, `_isSubmitting` 상태를 추적하여
리스트 리로드가 발생하면 폼을 초기화하는 방식으로 구현합니다.

### 5. 유저 플로우

```
1. 거래 입력 폼 진입
2. 날짜: 3/20, 카테고리: 생활비>식비, 결제수단: 신한카드
3. 금액: 15,000 / 내용: 점심
4. [x] 동일 항목 유지 체크
5. "저장 & 계속" 클릭
   → 저장 완료 스낵바 표시
   → 금액·내용·메모 초기화
   → 날짜: 3/20 유지, 카테고리: 생활비>식비 유지, 결제수단: 신한카드 유지
6. 금액: 5,500 / 내용: 커피
7. "저장 & 계속" 클릭 → 반복
8. 마지막 항목 → "저장" 클릭 → 이전 화면으로 돌아감
```

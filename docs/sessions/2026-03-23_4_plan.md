# NAS 서버 이전 계획
> 날짜: 2026-03-23 | 회차: 4 | 상태: 기획

## 요청 내용
Render free tier → 자작 NAS (Docker) 로 백엔드 이전

## 현재 NAS 상태
- Docker 사용 중
- DDNS: tiggle.duckdns.org
- 포트: 80 (tiggle FE), 8080 (tiggle BE)

## 이전 구성도

```
인터넷
  │
  ├── :80   → tiggle FE (기존, 변경 없음)
  ├── :8080 → tiggle BE (기존, 변경 없음)
  └── :443  → Caddy (HTTPS 리버스 프록시) [신규]
               └── budget-api.duckdns.org → budget-book-api:8090

NAS Docker 내부 네트워크 (budget-net)
  ├── caddy         (:443 외부)
  ├── budget-api    (:8090 내부)
  ├── budget-db     (:5432 내부, PostgreSQL)
  └── budget-redis  (:6379 내부, 선택)
```

## Step-by-Step

### Step 1: DuckDNS 서브도메인 등록
1. https://www.duckdns.org 로그인
2. `budget-api` 서브도메인 추가 → NAS 공인 IP와 동일하게 설정
3. 확인: `ping budget-api.duckdns.org` → NAS IP 응답

### Step 2: 라우터 포트포워딩
- 외부 443 → NAS 내부 IP:443 (TCP)

### Step 3: NAS에 Docker Compose 배포

`/opt/budget-book/docker-compose.yml` (또는 NAS의 Docker 디렉토리):

```yaml
version: "3.8"

services:
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports:
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
      - caddy_config:/config
    networks:
      - budget-net
    depends_on:
      - budget-api

  budget-api:
    image: budget-book-api:latest
    build:
      context: ./backend
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      SPRING_PROFILES_ACTIVE: prod
      DB_HOST: budget-db
      DB_PORT: 5432
      DB_NAME: budgetbook
      DB_USERNAME: budgetbook
      DB_PASSWORD: ${DB_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
      FRONTEND_URL: https://aiva-saas.github.io/budget-book
      GOOGLE_CLIENT_ID: ${GOOGLE_CLIENT_ID}
      GOOGLE_CLIENT_SECRET: ${GOOGLE_CLIENT_SECRET}
      KAKAO_CLIENT_ID: ${KAKAO_CLIENT_ID}
      KAKAO_CLIENT_SECRET: ${KAKAO_CLIENT_SECRET}
      REDIS_URL: redis://budget-redis:6379
      JAVA_OPTS: "-Xms256m -Xmx768m"
    networks:
      - budget-net
    depends_on:
      budget-db:
        condition: service_healthy

  budget-db:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: budgetbook
      POSTGRES_USER: budgetbook
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U budgetbook"]
      interval: 5s
      timeout: 5s
      retries: 5
    networks:
      - budget-net

  budget-redis:
    image: redis:7-alpine
    restart: unless-stopped
    networks:
      - budget-net

volumes:
  pgdata:
  caddy_data:
  caddy_config:

networks:
  budget-net:
```

### Step 4: Caddyfile (HTTPS 자동 발급)

```
budget-api.duckdns.org {
    reverse_proxy budget-api:8090

    tls {
        dns duckdns {env.DUCKDNS_TOKEN}
    }
}
```

> **참고**: Caddy의 DuckDNS DNS challenge를 위해
> `caddy-dns/duckdns` 플러그인이 포함된 커스텀 Caddy 이미지 필요
>
> Dockerfile.caddy:
> ```dockerfile
> FROM caddy:2-builder AS builder
> RUN xcaddy build --with github.com/caddy-dns/duckdns
> FROM caddy:2-alpine
> COPY --from=builder /usr/bin/caddy /usr/bin/caddy
> ```

### Step 5: 환경변수 (.env)
```env
DB_PASSWORD=강력한비밀번호
JWT_SECRET=64자이상의랜덤문자열
GOOGLE_CLIENT_ID=기존값
GOOGLE_CLIENT_SECRET=기존값
KAKAO_CLIENT_ID=기존값
KAKAO_CLIENT_SECRET=기존값
DUCKDNS_TOKEN=DuckDNS토큰
```

### Step 6: DB 마이그레이션 (Supabase → NAS PostgreSQL)

```bash
# 1. Supabase에서 덤프
pg_dump "postgresql://USER:PASS@HOST:PORT/DB?sslmode=require" \
  --no-owner --no-acl > backup.sql

# 2. NAS PostgreSQL로 복원
docker exec -i budget-db psql -U budgetbook budgetbook < backup.sql
```

### Step 7: OAuth2 Redirect URI 변경

**Google Cloud Console:**
- 승인된 리디렉션 URI 추가:
  `https://budget-api.duckdns.org/login/oauth2/code/google`

**Kakao Developers:**
- 리디렉션 URI 추가:
  `https://budget-api.duckdns.org/login/oauth2/code/kakao`

### Step 8: 프론트엔드 API URL 변경
- `frontend/lib/core/constants/` 또는 환경변수에서
- `https://budget-book-api.onrender.com` → `https://budget-api.duckdns.org`

### Step 9: 배포 자동화 (선택)

NAS에서 간단한 배포 스크립트:
```bash
#!/bin/bash
# deploy.sh
cd /opt/budget-book
git pull origin main
docker compose up -d --build budget-api
echo "Deploy complete: $(date)"
```

GitHub Actions에서 SSH로 트리거하거나, webhook으로 자동화 가능.

# Phase 13: 예산 계획 관리 고도화 (구매 목록 + 주차 배정 + 거래 연결)
> 날짜: 2026-03-29 | 회차: 2 | 상태: 기획

## 요청 내용
1. 기간 미정으로 사야 할 품목을 정리하고 저장해놓는 공간
2. 그 품목을 미래 예산 몇 주차에 사용할 예정인지 배정
3. 실제 사용 시 거래로 등록하여 전체 관리

## 핵심 컨셉

### 전체 플로우
```
[구매 목록] → [주차/날짜 배정] → [계획됨] → [거래 등록] → [완료]
  사야 할 것      언제 살지 결정     예산에 반영     실제 구매       추적 완료
```

### 상태 흐름
```
WISHLIST ──→ PLANNED ──→ COMPLETED
  (미정)      (날짜 배정)    (구매 완료)
    │            │
    │            └──→ SKIPPED (안 삼)
    │            └──→ OVERDUE (기한 초과)
    └──→ SKIPPED (삭제 대신 건너뛰기)
```

### 사용 시나리오
```
1. "에어프라이어 사야 하는데 언제 살지 모르겠다" → WISHLIST에 추가 (금액: ~15만원)
2. "4월 2주차에 사자" → 날짜 배정 → PLANNED (target_date: 4/7~4/13)
3. "쿠팡에서 14만원에 샀다" → 거래 등록 + 연결 → COMPLETED (실제 14만원)

또는:
1. "세제 사야 함" → WISHLIST
2. "이번 주 장보기에 포함" → 기존 코스트코 장보기 계획에 메모 추가
3. 장보기 거래 등록 시 한 번에 완료
```

## 기존 Phase 12와의 관계

Phase 12에서 구현한 `spending_plans` 테이블을 **확장**한다. 새 테이블 생성 없이 기존 구조를 활용.

### 변경 사항
| 항목 | Phase 12 (현재) | Phase 13 (확장) |
|------|----------------|----------------|
| target_date | NOT NULL (필수) | **NULL 가능** (WISHLIST는 날짜 없음) |
| status | PLANNED/COMPLETED/SKIPPED/OVERDUE | **+ WISHLIST** 추가 |
| priority | 없음 | **추가** (HIGH/MEDIUM/LOW) |
| estimated_min/max | 없음 | **추가** (가격 범위, 예: 10~15만원) |
| tags | 없음 | **추가** (태그로 분류: #생필품 #가전 #선물) |
| week_number | 없음 | **추가** (몇 주차에 배정했는지) |

## DB 변경

### V40 마이그레이션
```sql
-- 1. target_date를 nullable로 변경
ALTER TABLE spending_plans ALTER COLUMN target_date DROP NOT NULL;

-- 2. status CHECK에 WISHLIST 추가
ALTER TABLE spending_plans DROP CONSTRAINT ck_spending_plan_status;
ALTER TABLE spending_plans ADD CONSTRAINT ck_spending_plan_status
  CHECK (status IN ('WISHLIST', 'PLANNED', 'COMPLETED', 'SKIPPED', 'OVERDUE'));

-- 3. 새 컬럼 추가
ALTER TABLE spending_plans ADD COLUMN priority VARCHAR(10) DEFAULT 'MEDIUM';
ALTER TABLE spending_plans ADD CONSTRAINT ck_spending_plan_priority
  CHECK (priority IN ('HIGH', 'MEDIUM', 'LOW'));

ALTER TABLE spending_plans ADD COLUMN estimated_min BIGINT;
ALTER TABLE spending_plans ADD COLUMN estimated_max BIGINT;

ALTER TABLE spending_plans ADD COLUMN tags TEXT; -- comma-separated or JSON array

ALTER TABLE spending_plans ADD COLUMN week_number INT;
ALTER TABLE spending_plans ADD CONSTRAINT ck_spending_plan_week
  CHECK (week_number IS NULL OR (week_number >= 1 AND week_number <= 6));

-- 4. WISHLIST 전용 인덱스
CREATE INDEX idx_spending_plans_wishlist
  ON spending_plans(couple_id, status) WHERE status = 'WISHLIST';
```

## API 변경/추가

### 기존 API 수정
| API | 변경 내용 |
|-----|----------|
| POST /spending-plans | targetDate 선택적, status=WISHLIST 시 날짜 없이 생성 |
| GET /spending-plans | `?status=WISHLIST` 필터 추가, 날짜 없는 항목도 반환 |
| PUT /spending-plans/{id} | priority, estimatedMin/Max, tags, weekNumber 수정 가능 |

### 신규 API
| Method | Path | 설명 |
|--------|------|------|
| PATCH | /spending-plans/{id}/assign | WISHLIST → PLANNED 전환 (날짜/주차 배정) |
| GET | /spending-plans/wishlist | 구매 목록 전용 조회 (우선순위 정렬) |
| PATCH | /spending-plans/{id}/complete-with-transaction | 완료 + 거래 동시 생성 |

### PATCH /assign 요청
```json
{
  "targetDate": "2026-04-07",
  "weekNumber": 2,
  "budgetId": "uuid-식비예산"
}
```
→ status를 WISHLIST → PLANNED로 전환, 날짜/주차/예산 배정

### PATCH /complete-with-transaction 요청
```json
{
  "amount": 140000,
  "description": "에어프라이어 구매",
  "categoryId": "uuid-가전",
  "paymentMethodId": "uuid-체크카드",
  "transactionDate": "2026-04-08"
}
→ 거래 자동 생성 + 계획 COMPLETED + 거래 연결
```

## FE 화면 설계

### 1. 구매 목록 탭 (새로 추가)
기존 지출 계획 목록 페이지에 **2개 탭** 추가:

```
[계획됨] [구매 목록]
```

**구매 목록 탭**:
- 우선순위별 섹션 (🔴 높음 / 🟡 보통 / 🔵 낮음)
- 각 항목: 이름, 예상 금액(범위), 태그 칩, 카테고리
- 스와이프: 배정(→ 날짜 선택 팝업) / 삭제
- 길게 누르기: 우선순위 변경
- FAB: 구매 목록 추가

**구매 목록 추가 폼**:
- 품목명 (필수)
- 예상 금액 또는 범위 (10만~15만)
- 카테고리 (선택)
- 우선순위 (HIGH/MEDIUM/LOW)
- 태그 (자유 입력, 칩 형태)
- 메모

### 2. 주차 배정 플로우
구매 목록 항목에서 "배정" 클릭 시:

```
[주차 선택 팝업]
┌────────────────────────┐
│ 언제 구매할 예정인가요?   │
│                        │
│ 📅 이번 주 (3/24~3/30)  │
│ 📅 다음 주 (3/31~4/6)   │
│ 📅 4월 2주차 (4/7~4/13) │
│ 📅 직접 선택...          │
│                        │
│ 💰 예산: 식비 (잔여 22만) │
│                        │
│ [배정하기]               │
└────────────────────────┘
```

### 3. 거래 등록 + 완료 (원스텝)
계획된 항목에서 "구매 완료" 클릭 시:

```
[구매 완료]
┌────────────────────────┐
│ 에어프라이어              │
│ 계획: 150,000원          │
│                        │
│ 실제 금액: [140,000] 원   │
│ 결제수단: [체크카드 ▼]    │
│ 구매일: [2026-04-08 📅]  │
│                        │
│ ☑ 거래로 자동 등록        │
│                        │
│ [완료]                   │
└────────────────────────┘
```
→ 체크 시 거래 자동 생성 + 계획 완료 + 연결

### 4. 대시보드 위젯
홈 탭에 "구매 목록" 위젯 추가 (HomeConfigService에 등록):
- 우선순위 높은 항목 상위 3개 표시
- "N개 더 보기" 링크

## 성능 설계
- 구매 목록: couple_id + status='WISHLIST' 인덱스 활용, 가구당 ~20개 이내
- 주차 배정: 단순 UPDATE (status + target_date), 추가 쿼리 없음
- 거래 동시 생성: 트랜잭션 내 INSERT(transaction) + UPDATE(spending_plan) 원자적 처리
- tags: TEXT 컬럼 comma-separated, FE에서 split/join (검색 필요 시 향후 jsonb 전환)

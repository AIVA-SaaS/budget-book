## 1. 자산 간 이체 (Pocket Transfer)

### 개요
- 통장 A → 통장 B로 이체 기록
- 이체는 수입/지출이 아닌 **자산 이동**
- 총 자산에 영향 없음 (A -100만, B +100만)

### 데이터 모델
```sql
-- 기존 pocket_transfers 테이블 활용 또는 신규
CREATE TABLE pocket_transfers (
    id UUID PRIMARY KEY,
    couple_id UUID NOT NULL REFERENCES couples(id),
    from_pocket_id UUID NOT NULL REFERENCES money_pockets(id),
    to_pocket_id UUID NOT NULL REFERENCES money_pockets(id),
    amount BIGINT NOT NULL,
    transfer_date DATE NOT NULL,
    memo TEXT,
    author_id UUID NOT NULL REFERENCES users(id),
    visibility VARCHAR(10) NOT NULL DEFAULT 'SHARED',
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

### API
| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | `/api/v1/transfers` | 이체 생성 |
| GET | `/api/v1/transfers?year=&month=` | 이체 목록 조회 |
| PUT | `/api/v1/transfers/{id}` | 이체 수정 |
| DELETE | `/api/v1/transfers/{id}` | 이체 삭제 |

### 비즈니스 규칙
- from/to 포켓이 같으면 에러
- 이체 생성 시: from 포켓 잔액 감소, to 포켓 잔액 증가
- 이체 삭제 시: 역방향 잔액 반영
- 이체 수정 시: 기존 이체 취소 → 새 이체 적용

### UI
- 거래 추가 화면에 "이체" 타입 추가 (지출/수입/이체)
- 이체 선택 시: 출금 포켓, 입금 포켓, 금액, 날짜, 메모
- 거래 목록에서 이체는 별도 아이콘 (↔) 표시
- 포켓 상세에서 이체 내역 포함

## 2. 자산 현재 잔액 (Pocket Balance)

### 개요
- 각 포켓(통장/현금/저축 등)의 **현재 잔액** 표시
- 잔액 = 초기금액 + 수입 - 지출 + 받은이체 - 보낸이체
- 전체 자산 합계 표시

### 잔액 계산 방식

**옵션 A: 실시간 계산 (쿼리)**
```sql
SELECT p.id, p.name,
       p.initial_balance
       + COALESCE(SUM(CASE WHEN t.type='INCOME' THEN t.amount ELSE 0 END), 0)
       - COALESCE(SUM(CASE WHEN t.type='EXPENSE' THEN t.amount ELSE 0 END), 0)
       + COALESCE(transfer_in, 0)
       - COALESCE(transfer_out, 0)
       AS current_balance
FROM money_pockets p
LEFT JOIN transactions t ON t.pocket_id = p.id
...
```

**옵션 B: 스냅샷 + 증분 (성능 최적화)**
- `pocket_balance_snapshots` 테이블로 일/월 단위 스냅샷
- 최근 스냅샷 이후 거래만 계산
- 대량 데이터 시 유리

**추천: 옵션 A** (현재 데이터 규모에서 충분, 단순함)

### 필요한 변경
- `money_pockets` 테이블에 `initial_balance BIGINT DEFAULT 0` 컬럼 추가
- 포켓 생성/수정 시 초기 잔액 설정 가능
- 포켓 목록 API에 `currentBalance` 필드 추가

### UI
- **자산 관리 탭 (기존 또는 신규)**
  - 전체 자산 합계 카드
  - 포켓별 잔액 목록 (이름, 잔액, 유형)
  - 포켓 탭하면 상세 (거래 내역 + 이체 내역)
- **홈 탭**에 "총 자산" 카드 추가 (선택)

## 3. 카드 사용액 / 결제 예정 금액

### 개요
- 이번 달 카드(신용) 사용 합계 → **다음 달 결제 예정 금액**
- 결제일(settlementDay) 기준으로 결제 주기 계산
- 카드별 사용액 + 전체 합계

### 기존 인프라
- `payment_methods` 테이블에 이미 `type` (CREDIT/DEBIT/CASH/BANK), `settlement_day` 필드 있음
- `transactions` 테이블에 `settlement_date` 필드 있음
- `TransactionRepository.sumBySettlementDateGroupedByPaymentMethod` 쿼리 이미 존재

### 결제 예정 금액 계산
```
카드 결제일: 매월 15일
이번 달 사용 기간: 전월 16일 ~ 이번 달 15일
다음 달 결제 예정: 이번 달 16일 ~ 다음 달 15일 사용분
```

### API
| Method | Endpoint | 설명 |
|--------|----------|------|
| GET | `/api/v1/cards/summary?year=&month=` | 카드별 이번 달 사용액 + 결제 예정 |
| GET | `/api/v1/cards/{id}/transactions?year=&month=` | 특정 카드 거래 내역 |

### 응답 구조
```json
{
  "cards": [
    {
      "cardId": "uuid",
      "cardName": "삼성카드",
      "settlementDay": 15,
      "thisMonthUsage": 450000,
      "nextMonthPayment": 380000,
      "transactionCount": 23
    }
  ],
  "totalThisMonth": 850000,
  "totalNextMonth": 720000
}
```

### UI
- **카드 결제 현황 카드** (홈 탭 또는 자산 탭)
  - 이번 달 총 카드 사용: XXX원
  - 다음 달 결제 예정: XXX원
  - 카드별 펼치기 → 개별 사용액/결제 예정
- **카드 상세**: 해당 카드 거래 목록 (결제 주기별 필터)

## 작업 순서 (추천)

| 순서 | 기능 | 의존성 | 난이도 |
|------|------|--------|--------|
| 1 | 자산 잔액 표시 | money_pockets 확장 | M |
| 2 | 카드 사용액/결제 예정 | 기존 인프라 활용 | M |
| 3 | 자산 간 이체 | 잔액 기능 필요 | L |

### 이유
- 잔액이 먼저 있어야 이체의 결과를 확인할 수 있음
- 카드 결제 예정은 기존 쿼리/데이터로 바로 구현 가능
- 이체는 가장 복잡 (양방향 잔액 반영, 트랜잭션 정합성)

---

## 성능 설계
- **잔액 계산**: 포켓당 1회 집계 쿼리 (거래 수 1000건 이하면 < 50ms)
- **카드 결제 예정**: GROUP BY payment_method_id 단일 쿼리
- **이체**: 단일 트랜잭션 내 두 포켓 잔액 업데이트 (atomic)
- **데이터 규모**: 포켓 5~20개, 카드 2~5장, 월 거래 100~500건 → 실시간 계산 충분

# 이체 금액 전체 반영 — 공통화 기획
> 날짜: 2026-04-02 | 회차: 4 | 상태: 기획

## 핵심 문제
이체(Transfer) 금액이 **결제수단별 통계에만** 반영되고, 나머지 **11개 표시 위치에서 누락**됨.
사용자 기대: "이체로 나간 돈은 지출, 들어온 돈은 수입으로 **모든 곳**에서 일관되게 표시"

## 수정 범위 (BE 4개 서비스 + FE 자동 반영)

### BE 수정 (핵심)

**1. StatisticsService.getMonthlySummary()** → 이체 출금을 지출에 포함
- `totalExpense += 이체 출금 합계`
- `totalIncome += 이체 입금 합계` (선택적)
- Response에 `transferOut`, `transferIn` 필드 추가

**2. StatisticsService.getMonthlyTrend()** → 각 월별 이체 포함
- 12개월 트렌드 데이터에 이체 출금 포함

**3. ReportService.getMonthlyReport()** → 월 총 수입/지출에 이체 포함
- `totalExpense += transferOut`
- `totalIncome += transferIn`
- 요일별 패턴에 이체 일자 포함

**4. ReportService.getWeeklyReport()** → 주간 지출에 이체 포함
- 주간별 `totalSpent += transferOut`

**5. TransactionService.listTransactions()** → serverTotal에 이체 포함 (선택적)
- 현재 FE에서 합산하고 있으므로 BE에서 합산하면 중복 제거 가능

### FE 수정 (BE 변경에 따른 자동 반영)
- Entity/Model에 `transferOut`/`transferIn` 필드 추가 (필요한 경우)
- transaction_list_page.dart의 FE 합산 로직 제거 (BE에서 합산하면)

### 수정하지 않는 항목
- **예산**: 카테고리별 예산이므로 이체(카테고리 없음)는 포함 불가 → 설계 상 정상
- **주간 예산**: 동일 사유
- **그룹별 지출**: 이체는 카테고리 그룹이 없으므로 제외 → 정상

## 성능 설계
- 각 서비스에 TransferRepository 1~2개 추가 쿼리 (월별 출금/입금 합계)
- 기존 쿼리에 JOIN이 아닌 별도 쿼리 → 기존 성능 영향 없음
- 2명 사용 환경에서 이체 건수 극소 → 성능 무시 가능

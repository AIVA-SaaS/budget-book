# 로드맵: 예산 사용 계획 + 앱 배포 + 알림 서비스
> 날짜: 2026-03-29 | 회차: 1 | 상태: 기획

## 개요
3가지 고도화 방향을 우선순위와 의존관계를 고려하여 Phase 단위로 정리한다.

```
Phase 12: 예산 사용 계획 (Spending Plan)
Phase 13: 알림 서비스 (Notification)
Phase 14: 모바일 앱 배포 (Android/iOS)
```

---

## Phase 12: 예산 사용 계획 (Spending Plan)

### 목적
예산 안에서 "뭘, 언제, 얼마에 쓸 것인가"를 계획하고, 실제 사용 여부를 추적.

### 핵심 기능
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 계획 CRUD | 이름, 금액, 목표일, 카테고리, 결제수단 | P0 |
| 상태 추적 | PLANNED → COMPLETED/SKIPPED/OVERDUE | P0 |
| 예산 연동 | 예산별 계획 금액 합계, 여유 금액 표시 | P0 |
| 거래 수동 연결 | 계획 상세에서 거래 선택하여 연결 | P1 |
| 거래 자동 제안 | 거래 추가 시 매칭 계획 제안 | P2 |
| 반복 계획 | 매주/매월 자동 생성 | P2 |
| 주간 계획 뷰 | 이번 주 계획 타임라인 | P1 |
| 대시보드 위젯 | 오늘/이번 주 계획 카드 | P1 |

### 구현 범위
- **BE**: spending_plans 테이블 + CRUD API + 요약 API + 거래 매칭 API
- **FE**: 계획 목록/폼/상세, 예산 탭 연동, 대시보드 위젯
- **상세 설계**: `docs/sessions/2026-03-28_2_plan.md` 참조

### 예상 작업량
| 담당 | 작업 | 규모 |
|------|------|------|
| Contract | DB 마이그레이션 + API spec | S |
| BE | CRUD + Summary + Suggestion API | L |
| FE | 목록/폼/상세 + BLoC + 예산 탭 연동 | L |
| FE | 대시보드 위젯 + 주간 뷰 | M |

### 선행 조건
- 없음 (독립 기능)

## Phase 13: 알림 서비스 (Notification)

### 목적
사용자가 앱을 열지 않아도 중요한 이벤트를 인지할 수 있도록 푸시 알림 제공.

### 현재 상태
| 구분 | 상태 | 비고 |
|------|------|------|
| BudgetAlertService | ✅ 구현됨 | 80%/100% 초과 감지, pull 방식 |
| WebSocket | ✅ 구현됨 | STOMP 실시간 동기화, 커플 채널 |
| 스케줄러 | ✅ 3개 활성 | 반복거래(6AM), 카드정산(7AM), 토큰정리(3AM) |
| Firebase | ❌ 미설정 | FCM 미연동, SDK 미설치 |
| 알림 UI | ❌ 미구현 | 알림 센터, 설정 없음 |

### 알림 유형 설계

#### Tier 1 — 인앱 알림 (WebSocket 활용, Phase 13a)
Firebase 없이 앱 내에서 실시간 알림. 구현 난이도 낮음.

| 알림 | 트리거 | 수신자 |
|------|--------|--------|
| 예산 80% 도달 | 거래 추가 시 BudgetAlertService 체크 | 본인+배우자 |
| 예산 100% 초과 | 거래 추가 시 체크 | 본인+배우자 |
| 배우자 거래 추가 | WebSocket 이벤트 확장 | 배우자 |
| 반복 거래 실행 | 스케줄러 실행 후 | 본인 |
| 지출 계획 기한 임박 | 스케줄러 D-1 체크 | 본인 |
| 지출 계획 기한 초과 | 스케줄러 D+1 체크 | 본인 |

**구현**:
- BE: `notifications` 테이블 (type, title, message, isRead, createdAt)
- BE: `NotificationService` — 알림 생성 + WebSocket 푸시
- FE: 앱바 벨 아이콘 + 알림 드롭다운/페이지
- FE: 알림 설정 (유형별 ON/OFF)

#### Tier 2 — 네이티브 푸시 알림 (FCM, Phase 13b)
앱을 닫아도 알림 수신. 모바일 앱 배포 후 의미 있음.

| 알림 | 트리거 | 비고 |
|------|--------|------|
| 예산 초과 | 서버 감지 → FCM push | 백그라운드 수신 |
| 계획 리마인더 | 스케줄러 → FCM push | 오전 알림 |
| 보험 납부일 알림 | D-3 스케줄러 | 사전 알림 |
| 카드 정산일 알림 | D-1 스케줄러 | 정산 리마인더 |

**구현**:
- Firebase 프로젝트 생성 + google-services.json + GoogleService-Info.plist
- BE: FCM 토큰 관리 + 서버 → FCM API 호출
- FE: firebase_messaging 패키지 + 토큰 등록 + 포그라운드/백그라운드 핸들러
- FE: 알림 권한 요청 플로우

### 예상 작업량
| Phase | 담당 | 작업 | 규모 |
|-------|------|------|------|
| 13a | Contract | notifications 테이블 + API spec | S |
| 13a | BE | NotificationService + 이벤트 연동 | M |
| 13a | FE | 알림 UI (벨 아이콘 + 목록 + 설정) | M |
| 13b | BE | FCM 토큰 관리 + push API 연동 | M |
| 13b | FE | Firebase 설정 + 토큰 등록 + 핸들러 | M |
| 13b | DevOps | Firebase 프로젝트 셋업 | S |

### 선행 조건
- Phase 13a: 없음 (독립)
- Phase 13b: 모바일 앱 빌드 환경 (Phase 14와 병행 가능)

## Phase 14: 모바일 앱 배포 (Android/iOS)

### 목적
현재 웹 전용 서비스를 모바일 앱으로 배포하여 사용성 향상.

### 현재 상태
| 구분 | 상태 | 비고 |
|------|------|------|
| Flutter 프로젝트 | ✅ 웹+모바일 통합 | 단일 코드베이스 |
| Android 설정 | ⚠️ 기본 scaffold | 빌드 가능하나 미배포 |
| iOS 설정 | ⚠️ 기본 scaffold | Xcode 프로젝트 존재 |
| OAuth redirect | ⚠️ 웹 전용 | 딥링크/커스텀 스킴 필요 |
| API base URL | ✅ dart-define | 빌드 시 주입 가능 |

### 배포 전략

#### Phase 14a — Android (우선)
1. **앱 서명 키 생성** (keystore)
2. **AndroidManifest 설정**: 딥링크, 권한, 아이콘
3. **OAuth2 모바일 플로우**: Custom URI scheme (`com.budgetbook://oauth/callback`)
4. **빌드**: `flutter build apk --release` or `flutter build appbundle`
5. **배포**: Google Play Console 등록 또는 APK 직접 배포 (NAS 공유)
6. **CI/CD**: GitHub Actions에 Android 빌드 워크플로우 추가

#### Phase 14b — iOS
1. **Apple Developer 계정** 필요 ($99/년)
2. **Provisioning Profile + Certificate** 설정
3. **Xcode 프로젝트 설정**: Bundle ID, 권한, 아이콘
4. **OAuth2**: Universal Links 또는 Custom URL scheme
5. **빌드**: `flutter build ipa`
6. **배포**: TestFlight → App Store 또는 Ad Hoc

### 모바일 전환 시 추가 고려사항

| 항목 | 웹 현재 | 모바일 변경 필요 |
|------|--------|----------------|
| OAuth 로그인 | 브라우저 리다이렉트 | 딥링크 or WebView 기반 |
| 토큰 저장 | flutter_secure_storage | 동일 (이미 지원) |
| API URL | dart-define | 동일 |
| 날짜 캘린더 | 커스텀 Dialog | 동일 (Flutter 네이티브) |
| 파일 저장 | 없음 | CSV 내보내기 시 path_provider |
| 알림 | 없음 | FCM (Phase 13b) |
| 오프라인 | 미지원 | 향후 SQLite 캐시 고려 |

### 예상 작업량
| Phase | 담당 | 작업 | 규모 |
|-------|------|------|------|
| 14a | FE | Android 빌드 설정 + OAuth 딥링크 | M |
| 14a | BE | 모바일 OAuth redirect URI 등록 | S |
| 14a | DevOps | GitHub Actions Android 빌드 + NAS APK 배포 | M |
| 14b | FE | iOS 빌드 설정 + Universal Links | M |
| 14b | DevOps | Apple Developer + TestFlight CI | M |

### 선행 조건
- OAuth 딥링크 변경 → BE SecurityConfig 수정 필요
- FCM 알림 → Phase 13b와 병행

## 진행 순서 권장

```
Phase 12 (Spending Plan)     ━━━━━━━━━━━━━ [2~3세션]
Phase 13a (인앱 알림)         ━━━━━━━━ [1~2세션]
Phase 14a (Android 배포)            ━━━━━━━━ [1~2세션]
Phase 13b (FCM 푸시)                      ━━━━ [1세션]
Phase 14b (iOS 배포)                            ━━━━ [1~2세션]
```

**이유**:
1. **Phase 12 먼저**: 독립 기능, 즉시 사용 가능, 기존 예산 기능의 핵심 확장
2. **Phase 13a**: 인앱 알림은 Firebase 없이 구현 가능, 웹에서도 동작
3. **Phase 14a**: Android 우선 배포 (Apple 개발자 계정 불필요)
4. **Phase 13b**: 모바일 앱 배포 후 FCM 연동 (앱이 있어야 의미 있음)
5. **Phase 14b**: iOS는 Apple 계정 준비 후

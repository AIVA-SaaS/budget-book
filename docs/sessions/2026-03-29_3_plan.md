# 고도화: 고객 피드백 게시판 + 배포 노트 + 커뮤니티
> 날짜: 2026-03-29 | 회차: 3 | 상태: 기획

## 요청 내용
1. 사용자가 불만/기능 개선/기능 추가 요청을 남길 수 있는 게시판
2. 개선/추가 내용의 배포 노트를 연결하여 사용자에게 알림
3. 향후 커뮤니티 확장 가능한 설계

## 현재 상태
| 구분 | 상태 | 비고 |
|------|------|------|
| 공지사항 | ✅ 구현됨 | Announcement CRUD + 홈 배너 |
| 관리자 대시보드 | ✅ 구현됨 | 사용자 관리 + 통계 |
| 피드백/게시판 | ❌ 없음 | |
| 배포 노트 | ❌ 없음 | |
| 알림 시스템 | ❌ 빈 디렉토리만 | |

## 설계

### 전체 구조

```
[사용자 앱]
├── 설정 > 피드백 및 공지
│   ├── 📢 공지사항 (기존 Announcement 확장)
│   ├── 📝 요청/피드백 (신규)
│   │   ├── 내 요청 목록
│   │   ├── 요청 작성 (카테고리: 버그/개선/기능추가)
│   │   └── 요청 상세 (상태 추적 + 관리자 답변)
│   └── 🚀 업데이트 내역 (신규)
│       ├── 버전별 배포 노트
│       └── 요청 연결 ("내 요청이 반영되었습니다!")
│
[관리자]
├── 관리자 대시보드 (기존)
│   ├── 피드백 관리 (신규)
│   │   ├── 전체 요청 목록 (필터: 상태/카테고리)
│   │   ├── 요청 상태 변경 (접수→검토→개발중→완료→반려)
│   │   └── 관리자 답변 작성
│   └── 배포 노트 관리 (신규)
│       ├── 배포 노트 작성
│       └── 피드백 연결 (어떤 요청이 반영되었는지)
```

### 1. 피드백/요청 게시판

#### 사용자 플로우
```
[피드백] 탭 클릭
  → 내 요청 목록 (최신순)
  → [+ 새 요청] FAB
      → 카테고리 선택: 🐛 버그 신고 / 💡 기능 개선 / ✨ 기능 추가 / 💬 기타
      → 제목 입력
      → 내용 입력 (마크다운 또는 일반 텍스트)
      → 스크린샷 첨부 (선택, 향후)
      → [제출]

  → 요청 상세
      → 상태 표시: 접수 → 검토 중 → 개발 중 → 완료 / 반려
      → 관리자 답변 (타임라인 형태)
      → 연결된 배포 노트 (해결된 경우)
```

#### 상태 흐름
```
SUBMITTED ──→ REVIEWING ──→ IN_PROGRESS ──→ RESOLVED
  (접수)        (검토 중)      (개발 중)       (완료)
                    │                          │
                    └──→ REJECTED             연결: 배포 노트
                          (반려, 사유 포함)
```

### 2. 배포 노트 (Release Notes)

#### 구조
```
[업데이트 내역]
├── v1.3.0 — 2026-03-29
│   ├── ✨ 지출 계획 기능 추가
│   ├── 🐛 주간 예산 금액 계산 수정
│   ├── 💡 카테고리 선택 UI 개선
│   └── 📎 관련 요청: #12, #15 (사용자 요청 연결)
│
├── v1.2.0 — 2026-03-25
│   ├── ✨ 이체 기능
│   └── ...
```

#### 사용자 알림
- 새 배포 노트 등록 시 → 홈 배너 또는 인앱 알림
- 내 요청이 반영된 배포 노트 → "🎉 요청하신 기능이 반영되었습니다!" 개별 알림

### 3. 관리자 피드백 관리

```
[관리자 > 피드백 관리]
├── 전체 요청 리스트 (필터: 상태, 카테고리, 날짜)
├── 요청 상세
│   ├── 상태 변경 드롭다운
│   ├── 답변 작성 (마크다운)
│   ├── 배포 노트 연결 (RESOLVED 시)
│   └── 내부 메모 (사용자 비공개)
└── 통계: 카테고리별 요청 수, 평균 처리 시간
```

## DB 설계

### V41: feedback_posts (피드백/요청)
```sql
CREATE TABLE feedback_posts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id),
  category VARCHAR(20) NOT NULL,  -- BUG, IMPROVEMENT, FEATURE, OTHER
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'SUBMITTED',
    -- SUBMITTED, REVIEWING, IN_PROGRESS, RESOLVED, REJECTED
  admin_note TEXT,                 -- 관리자 내부 메모 (사용자 비공개)
  resolved_release_id UUID,       -- 해결된 배포 노트 연결
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),

  CONSTRAINT ck_feedback_category CHECK (category IN ('BUG', 'IMPROVEMENT', 'FEATURE', 'OTHER')),
  CONSTRAINT ck_feedback_status CHECK (status IN ('SUBMITTED', 'REVIEWING', 'IN_PROGRESS', 'RESOLVED', 'REJECTED'))
);

CREATE INDEX idx_feedback_user ON feedback_posts(user_id, created_at DESC);
CREATE INDEX idx_feedback_status ON feedback_posts(status);
```

### V42: feedback_comments (관리자 답변 / 사용자 추가 코멘트)
```sql
CREATE TABLE feedback_comments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  post_id UUID NOT NULL REFERENCES feedback_posts(id) ON DELETE CASCADE,
  author_id UUID NOT NULL REFERENCES users(id),
  content TEXT NOT NULL,
  is_admin_reply BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

  CONSTRAINT fk_comment_post FOREIGN KEY (post_id) REFERENCES feedback_posts(id) ON DELETE CASCADE
);

CREATE INDEX idx_feedback_comments_post ON feedback_comments(post_id, created_at);
```

### V43: release_notes (배포 노트)
```sql
CREATE TABLE release_notes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  version VARCHAR(20) NOT NULL,    -- 'v1.3.0'
  title VARCHAR(200) NOT NULL,
  content TEXT NOT NULL,           -- 마크다운 배포 내용
  is_published BOOLEAN NOT NULL DEFAULT FALSE,
  published_at TIMESTAMPTZ,
  created_by UUID NOT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX idx_release_notes_version ON release_notes(version);
```

### V44: release_note_feedbacks (배포 노트 ↔ 피드백 연결)
```sql
CREATE TABLE release_note_feedbacks (
  release_note_id UUID NOT NULL REFERENCES release_notes(id) ON DELETE CASCADE,
  feedback_post_id UUID NOT NULL REFERENCES feedback_posts(id) ON DELETE CASCADE,
  PRIMARY KEY (release_note_id, feedback_post_id)
);
```

## 고도화 확장 방향

### Phase A (기본 — 이번 구현)
- 피드백 CRUD + 상태 관리
- 관리자 답변
- 배포 노트 CRUD + 발행
- 피드백 ↔ 배포 노트 연결

### Phase B (중기 고도화)
- 스크린샷/이미지 첨부 (S3 또는 NAS 파일 저장)
- 피드백 투표 (다른 사용자가 "나도 필요해요" 👍)
- 공개 피드백 보드 (다른 사용자의 요청도 볼 수 있게)
- 인앱 알림: "내 요청이 반영되었습니다", "관리자가 답변했습니다"

### Phase C (장기 고도화)
- 커뮤니티 게시판 (자유 게시판, 가계부 노하우 공유)
- 댓글 대댓글
- 사용자 간 커플 매칭/초대 게시판
- 가계부 템플릿 공유 (카테고리 구성, 예산 설정 공유)

## 성능 설계
- 피드백 목록: user_id 인덱스, 페이징 처리 (사용자당 ~10-50건)

- 피드백↔배포 연결: 조인 테이블, 배포당 ~5-10건 피드백 연결

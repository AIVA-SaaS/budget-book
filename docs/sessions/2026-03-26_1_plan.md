# 홈 탭 결제수단별 거래 내역 + 거래 합계 개선 + 무한 스크롤 + 표시 설정
> 날짜: 2026-03-26 | 회차: 1 | 상태: 기획

## 요청 내용
1. 홈 탭 하단에 결제수단별 최근 거래 내역 표시 + 클릭 시 전체 내역
2. 홈 탭 최근 거래 개수 사용자 설정 (5개/10개/1개월)
3. 거래 탭 합계: 월 전체 서버 집계 표시 (로드된 항목 기반이 아닌)
4. 무한 스크롤 자연스럽게 개선 (pre-fetch, 웹/모바일 고려)

## 상세 설계

### Feature 1: 홈 탭 결제수단별 최근 거래 내역

**변경**: _PaymentMethodSummaryCard를 결제수단별 거래 그룹으로 교체

```
[결제수단] 카드
  ├─ [신한카드]  잔고: -
  │   점심식사       -12,000원
  │   편의점          -3,500원
  │   더보기 →
  ├─ [현금]  잔고: 50,000원
  │   ATM 출금       -50,000원
  │   더보기 →
```

**구현 방법**:
- DashboardBloc에서 각 활성 결제수단의 최근 거래 2~3건씩 로드
- 성능: 결제수단이 보통 3~5개이므로 API 호출 3~5개 추가
- 대안: BE에 결제수단별 그룹 API 추가 대신, FE에서 기존 recentTransactions를 paymentMethodId로 그룹핑
  → recentTransactions 수를 충분히 가져오면 (20~30건) 그룹핑 가능
  → 가장 적은 변경으로 구현 가능

**선택: FE 그룹핑 방식** (BE 변경 없음)
- recentTransactions를 paymentMethodId별로 groupBy
- 각 그룹에서 최근 2건만 표시
- "더보기" 클릭 시 해당 결제수단 거래 목록으로 이동

### Feature 2: 최근 거래 표시 개수 설정

**CouplePrefs key**: `dashboard_recent_count`
- 값: "5", "10", "30" (1개월은 size=30으로 근사)
- 기본값: "5"

**설정 UI**: 설정 페이지에 "홈 화면 최근 거래" 드롭다운
- 5개 / 10개 / 30개(1개월)

**DashboardBloc**: CouplePrefs에서 count 읽어서 API size에 사용

### Feature 3: 거래 탭 월 전체 합계

**현재 문제**: `TransactionLoaded.totalIncome/totalExpense`가 로드된 거래에서 계산
**해결**: 통계 summary API를 병렬 호출하여 서버 집계 사용

- `TransactionBloc._onLoadTransactions()`: 거래 목록 + statistics/summary 병렬 호출
- `TransactionLoaded`: `serverTotalIncome`, `serverTotalExpense` 필드 추가
- `MonthSummaryBar`: 서버 집계 값 사용
- 필터 적용 시(결제수단별 등): 서버 집계 대신 로드된 항목 집계 사용 (필터별 집계 API 없으므로)

### Feature 4: 무한 스크롤 개선

**현재**: 80% 지점에서 pre-fetch (이미 구현, 라인 522-523)
**개선사항**:
- 현재 NotificationListener + ScrollUpdateNotification 방식은 정상
- 80% threshold → 70%로 조정 (더 일찍 로드)
- 로딩 인디케이터: 현재 있음 (리스트 마지막 항목)
- 웹/모바일 고려: 웹은 화면이 넓어 한 번에 더 많은 항목 표시 → size를 30으로 증가 (현재 30으로 이미 설정)

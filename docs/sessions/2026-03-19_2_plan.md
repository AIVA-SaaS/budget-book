## 공통 모듈 설계

### 모듈 A: `ReorderableEntityList<T>` (FE 공통 위젯)
**위치**: `frontend/lib/core/widgets/reorderable_entity_list.dart`

드래그앤드롭 순서 변경이 가능한 범용 리스트 위젯.

```dart
class ReorderableEntityList<T> extends StatelessWidget {
  final List<T> items;
  final Widget Function(BuildContext, T, int index) itemBuilder;
  final void Function(int oldIndex, int newIndex) onReorder;
  final Widget Function(BuildContext, T)? dragHandleBuilder;
  final bool enabled; // 편집 모드 on/off
}
```

**적용 가능 영역**:
- 카테고리 그룹 순서 변경 ← 이번 작업
- 결제수단 순서 변경 (payment_methods.display_order 이미 존재)
- 카테고리 그룹 내 하위 카테고리 순서 변경 (categories.display_order 이미 존재)
- 예산 목록 정렬, 포켓 순서 등

### 모듈 B: `HierarchicalSelectorSheet<G, I>` (FE 공통 위젯)
**위치**: `frontend/lib/core/widgets/hierarchical_selector_sheet.dart`

그룹-아이템 2단계 계층 구조에서 그룹 또는 아이템을 선택할 수 있는 범용 바텀시트.

```dart
class HierarchicalSelectorSheet<G, I> extends StatefulWidget {
  final List<G> groups;
  final List<I> Function(G group) itemsOf;          // 그룹에서 아이템 추출
  final String Function(G) groupLabel;               // 그룹 표시명
  final String Function(I) itemLabel;                // 아이템 표시명
  final Color? Function(G)? groupColor;              // 그룹 색상
  final Color? Function(I)? itemColor;               // 아이템 색상
  final String? Function(G)? groupId;                // 그룹 ID
  final String? Function(I)? itemId;                 // 아이템 ID
  final bool groupSelectable;                         // 그룹 자체 선택 가능 여부
  final String? selectedGroupId;                      // 현재 선택된 그룹
  final String? selectedItemId;                       // 현재 선택된 아이템
  final void Function(G group)? onGroupSelected;      // 그룹 선택 콜백
  final void Function(I item)? onItemSelected;        // 아이템 선택 콜백
  final void Function(G group)? onAddItem;            // 아이템 추가 콜백
  final void Function()? onAddGroup;                  // 그룹 추가 콜백
  final void Function(I item)? onDeleteItem;          // 아이템 삭제 콜백
  final String title;                                 // 시트 타이틀
}
```

**적용 가능 영역**:
- 카테고리 선택 (거래 등록, 예산 설정) ← 이번 작업
- 결제수단 유형별 선택 (신용카드/체크카드/현금 그룹 → 개별 카드)
- 포켓 카테고리별 선택
- 향후 태그 그룹 → 태그 선택 등

### 모듈 C: `BatchReorderApi` (BE 공통 패턴)
**위치**: 각 Controller에 동일 패턴 적용

`display_order` 컬럼이 있는 모든 엔티티에 동일하게 적용 가능한 일괄 순서 변경 패턴.

```kotlin
// 공통 요청 DTO
data class ReorderRequest(val orderedIds: List<UUID>)

// 서비스에서 공통 로직
fun reorder(userId: UUID, orderedIds: List<UUID>) {
    val couple = getActiveCouple(userId)
    val entities = repository.findByCoupleId(couple.id)
    // 소유권 검증 + orderedIds 순서대로 displayOrder 할당
    orderedIds.forEachIndexed { index, id ->
        entities.find { it.id == id }?.displayOrder = index
    }
    repository.saveAll(entities)
}
```

**적용 가능 영역**:
- 카테고리 그룹 순서 ← 이번 작업
- 결제수단 순서 (display_order 이미 존재)
- 카테고리 순서 (display_order 이미 존재)
- 포켓 순서 등

## 기능별 설계

### 기능1: 드래그앤드롭 순서 변경

**BE**:
- `PUT /api/v1/category-groups/reorder` — `ReorderRequest { orderedIds }` 수신
- `CategoryGroupService.reorderGroups()` — 모듈C 패턴 적용
- 소유권 검증 + 단일 트랜잭션 일괄 업데이트

**FE**:
- `category_group_page.dart`에서 `ReorderableEntityList<CategoryGroup>` 사용
- 드래그 핸들(≡) 아이콘 우측 표시
- 드래그 완료 → `ReorderCategoryGroups(orderedIds)` BLoC 이벤트 → API 호출
- Optimistic update: 로컬 즉시 반영 → 실패 시 롤백

### 기능2: 기본 항목 삭제/수정 허용

**BE**:
- `CategoryService.deleteCategory()`: `isDefault` 체크 + throw 제거
- `CategoryGroupService.deleteCategoryGroup()`: `isDefault` 체크 + throw 제거
- 테스트: "기본 카테고리도 삭제 가능" 케이스로 변경

**FE**:
- `category_group_page.dart`: `!group.isDefault` 조건 제거
- `category_group_selector_sheet.dart`: `!category.isDefault` 조건 제거
- 삭제 확인 다이얼로그는 유지

### 기능3: 그룹 단위 예산

**DB 마이그레이션 (V25)**:
```sql
ALTER TABLE monthly_budgets
    ADD COLUMN group_id UUID REFERENCES category_groups(id) ON DELETE SET NULL;

-- Unique constraint 변경
DROP INDEX IF EXISTS uk_monthly_budgets_couple_category_month;
CREATE UNIQUE INDEX uk_monthly_budgets_couple_cat_group_month
    ON monthly_budgets (
        couple_id,
        COALESCE(category_id, '00000000-0000-0000-0000-000000000000'),
        COALESCE(group_id, '00000000-0000-0000-0000-000000000000'),
        year_month
    );

-- CHECK: category_id와 group_id 동시 설정 방지
ALTER TABLE monthly_budgets
    ADD CONSTRAINT ck_budget_category_or_group
    CHECK (category_id IS NULL OR group_id IS NULL);
```

**예산 3레벨**:
| 레벨 | category_id | group_id | 지출 합산 방식 |
|------|------------|----------|--------------|
| 전체 | NULL | NULL | 커플 전체 지출 합산 |
| 그룹 | NULL | 설정 | 그룹 하위 카테고리 지출 합산 |
| 카테고리 | 설정 | NULL | 해당 카테고리 지출만 |

**BE 변경**:
- `MonthlyBudget` entity: `group` (ManyToOne, nullable) 추가
- `BudgetDtos`: Request/Response에 `groupId`, `groupName` 추가
- `MonthlyBudgetRepository`: `existsByCoupleIdAndGroupIdAndYearMonth()` 추가
- `TransactionRepository`: `sumByGroupForCouple()` — group_id 기준 집계 쿼리 추가
- `BudgetService`: 생성/조회 시 그룹 예산 처리 로직

**FE 변경**:
- 기존 `CategoryGroupSelectorSheet` → `HierarchicalSelectorSheet`로 교체
  - `groupSelectable: true` 설정 시 그룹 클릭 = 선택, 토글은 우측 화살표 아이콘 전용
  - `groupSelectable: false` 설정 시 기존 동작 (거래 등록에서 사용)
- `budget_form_page.dart`: `_selectedGroupId` 추가, 그룹/카테고리 배타적 선택
- `budget_list_page.dart`: 그룹 예산 표시 (그룹 아이콘 + "(그룹)" 라벨)
- Budget entity/model: `groupId`, `groupName` 필드 추가

## 성능 설계
- **일괄 순서 업데이트**: 그룹 10~20개, 단일 트랜잭션 → 성능 이슈 없음
- **그룹별 지출 합산**: `JOIN categories ON group_id + SUM` — `idx_categories_group_id` 인덱스 활용 (V20)
- **HierarchicalSelectorSheet**: 제네릭 위젯이므로 빌드 비용은 기존과 동일

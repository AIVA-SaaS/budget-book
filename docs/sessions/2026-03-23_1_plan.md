# 그룹 예산 지출 집계 + 홈 탭 주간 예산 포함 수정
> 날짜: 2026-03-23 | 회차: 1 | 상태: 기획/검증완료

## 요청 내용
1. 생활비(그룹) 주간 예산 20만원(월환산 885,714) 설정 후, 하위 카테고리(구매, 식비) 지출이 집계되지 않음
2. 홈 탭 예산 사용 현황에 주간 예산이 포함되지 않음 (2~3번째 보고)

## 근본 원인 분석

### 문제 1: 그룹 지출 집계 실패 (BudgetService.kt:314-324)
```kotlin
val allCategories = categoryRepository.findByCoupleId(couple.id)
groupIds.associateWith { gId ->
    allCategories.filter { it.group?.id == gId }  // ← Hibernate lazy proxy 의존
        .sumOf { cat -> spendingByCategory[cat.id] ?: 0L }
}
```
- `findByCoupleId`는 Category의 `group` 필드를 JOIN FETCH 없이 로드
- `it.group?.id`는 Hibernate lazy proxy를 통해 접근 → mock 테스트에서는 직접 객체라 동작하지만, 프로덕션 Hibernate 6 (FIELD access) 환경에서 불안정
- **해결**: DB에서 직접 그룹별 지출을 집계하는 쿼리 추가 (lazy 의존 제거)

### 문제 2: BudgetAlertService 그룹 예산 미처리 (BudgetAlertService.kt:49-58)
```kotlin
val spentAmount = if (categoryId != null) {
    spendingByCategory[categoryId] ?: 0L
} else {
    totalExpense  // ← 그룹 예산도 여기로 빠짐. 전체 지출이 되어버림
}
```
- 그룹 예산(category=null, group≠null)을 전체 예산(category=null, group=null)과 동일하게 처리
- 그룹 예산의 지출이 전체 지출로 잘못 계산됨

### 문제 3: 홈 탭 미포함
- 커밋 0389ea3에서 WEEKLY 필터 제거로 summary에는 포함됨
- 하지만 spentAmount가 0이라 의미 없는 데이터로 표시
- 문제 1 수정 시 함께 해결됨

## 성능 설계
- **데이터 접근**: 기존 N+1 lazy 로딩 → 단일 GROUP BY 쿼리로 변경
  - `sumByCategoryGroupForCouple`: 트랜잭션 테이블 1회 쿼리 (GROUP BY category.group.id)
- **예상 규모**: 그룹 수 1~10개, 카테고리 수 10~50개, 트랜잭션 수 100~1000개/월
- **리소스 제약**: 없음 (기존보다 효율적)
- **설계 결정**: DB 레벨 집계 선택 — lazy loading 의존 제거, 쿼리 수 감소

## 신규 쿼리 설계

```sql
-- sumByCategoryGroupForCouple
SELECT t.category.group.id, SUM(t.amount)
FROM Transaction t
WHERE t.couple.id = :coupleId
  AND t.transactionDate BETWEEN :startDate AND :endDate
  AND t.type = :type
  AND t.category.group.id IN :groupIds
  AND (t.visibility = SHARED OR t.owner.id = :userId)
GROUP BY t.category.group.id
```

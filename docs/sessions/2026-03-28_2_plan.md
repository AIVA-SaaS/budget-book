# 고도화: 예산 사용 계획 (Budget Spending Plan)
> 날짜: 2026-03-28 | 회차: 2 | 상태: 기획

## 요청 내용
주간/월간 예산 사용 계획 기능. 사야 할 것과 금액을 적고, 언제 예산에서 해당 금액을 사용할지 설정하고, 실제 사용 여부를 추적하며, 지출 계획을 세울 수 있는 기능.

## 핵심 컨셉

### "예산 내 지출 계획표"
예산(Budget)이 **"이번 달 얼마까지 쓸 수 있는가"**라면,
지출 계획(Spending Plan)은 **"그 예산 안에서 뭘, 언제, 얼마에 살 것인가"**이다.

```
예산: 식비 50만원 (월간)
  └─ 계획 1: 코스트코 장보기 15만원 (3/2 토요일) → ✅ 완료 (실제 14.2만원)
  └─ 계획 2: 외식 8만원 (3/8 토요일) → ⏳ 예정
  └─ 계획 3: 생필품 5만원 (3/15) → 📝 계획됨
  └─ 미계획 지출: 22만원 남음 (자유 사용 가능)
```

## 기능 상세

### 1. 지출 계획 CRUD
- **항목**: 이름, 금액, 목표 날짜, 카테고리, 결제수단, 메모
- **연결**: 예산(Budget)에 선택적 연결 → 연결 시 해당 예산의 계획 금액에 반영
- **반복**: 일회성 or 반복(매주/매월) → 기존 RecurringTransaction 패턴 활용
- **공유**: SHARED/PRIVATE visibility (부부 공유 지출 계획 vs 개인)

### 2. 상태 추적
| 상태 | 의미 | 전환 조건 |
|------|------|----------|
| PLANNED | 계획됨 | 초기 상태 |
| COMPLETED | 완료 | 거래 연결 시 or 수동 완료 처리 |
| SKIPPED | 건너뜀 | 사용자가 이번엔 안 사기로 결정 |
| OVERDUE | 기한 초과 | 목표 날짜 지남 + 미완료 |

### 3. 거래 연결 (Transaction Linking)
계획과 실제 거래를 연결하여 "계획 vs 실제" 비교:

**자동 연결 (제안)**:
- 거래 추가 시 같은 카테고리 + 비슷한 금액(±20%) + 비슷한 날짜(±3일)의 미완료 계획이 있으면 "이 계획의 지출인가요?" 제안
- 사용자가 수락하면 연결, 계획 상태 → COMPLETED

**수동 연결**:
- 계획 상세에서 "거래 연결" 버튼 → 기존 거래 목록에서 선택
- 거래 추가 시 "계획된 지출" 드롭다운에서 직접 선택

### 4. 예산 연동 뷰
예산 탭에서 각 예산별로 계획 현황 표시:

```
[식비 예산: 50만원]
├─ 계획된 지출: 28만원 (3건)
├─ 실제 사용: 14.2만원 (1건 완료)
├─ 미계획 여유: 22만원
└─ 진행률: ██████░░░░ 56% 계획됨
```

### 5. 주간 계획 뷰
주간 예산과 연동하여 이번 주 계획 표시:

```
[이번 주 계획 - 3/24~3/30]
┌─────────────────────────────────┐
│ 📅 3/25 (화) 코스트코 장보기  15만원  ✅ │
│ 📅 3/28 (금) 외식           8만원  ⏳ │
│ 📅 3/29 (토) 주유          5만원  📝 │
│─────────────────────────────────│
│ 계획 합계: 28만원 / 주간 예산: 35만원   │
│ 여유: 7만원                         │
└─────────────────────────────────┘
```

### 6. 대시보드 위젯
홈 대시보드에 "오늘/이번 주 계획" 카드:
- 오늘 예정된 계획 항목
- 기한 초과(OVERDUE) 항목 알림
- 이번 주 계획 진행률

## DB 설계

### 신규 테이블: `spending_plans`
```sql
CREATE TABLE spending_plans (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  couple_id UUID NOT NULL REFERENCES couples(id),
  author_id UUID NOT NULL REFERENCES users(id),

  -- 계획 내용
  name VARCHAR(100) NOT NULL,
  amount BIGINT NOT NULL,
  target_date DATE NOT NULL,
  memo TEXT,

  -- 연결
  category_id UUID REFERENCES categories(id),
  payment_method_id UUID REFERENCES payment_methods(id),
  budget_id UUID REFERENCES monthly_budgets(id),
  linked_transaction_id UUID REFERENCES transactions(id),

  -- 상태
  status VARCHAR(20) NOT NULL DEFAULT 'PLANNED',
    -- PLANNED, COMPLETED, SKIPPED, OVERDUE
  actual_amount BIGINT,                -- 실제 사용 금액 (완료 시)
  completed_date DATE,                 -- 실제 완료 날짜

  -- 반복 (일회성이면 NULL)
  is_recurring BOOLEAN DEFAULT FALSE,
  frequency VARCHAR(20),               -- WEEKLY, MONTHLY
  recurring_source_id UUID REFERENCES spending_plans(id),
    -- 반복 생성의 원본 계획 ID

  -- 공유
  visibility VARCHAR(10) NOT NULL DEFAULT 'SHARED',
  owner_id UUID REFERENCES users(id),

  -- 타임스탬프
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),

  -- 제약조건
  CONSTRAINT ck_spending_plan_status
    CHECK (status IN ('PLANNED', 'COMPLETED', 'SKIPPED', 'OVERDUE')),
  CONSTRAINT ck_spending_plan_visibility
    CHECK (visibility IN ('SHARED', 'PRIVATE')),
  CONSTRAINT ck_spending_plan_frequency
    CHECK (frequency IS NULL OR frequency IN ('WEEKLY', 'MONTHLY'))
);

-- 인덱스
CREATE INDEX idx_spending_plans_couple_date
  ON spending_plans(couple_id, target_date);
CREATE INDEX idx_spending_plans_budget
  ON spending_plans(budget_id) WHERE budget_id IS NOT NULL;
CREATE INDEX idx_spending_plans_status
  ON spending_plans(couple_id, status) WHERE status = 'PLANNED';
```

## API 설계

### 엔드포인트
| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/v1/spending-plans` | 계획 목록 (기간/상태 필터) |

## FE 화면 설계

### 1. 지출 계획 목록 페이지
- 주간/월간 뷰 전환
- 날짜별 그룹핑 (타임라인 형태)
- 상태별 필터 (전체/계획됨/완료/건너뜀/기한초과)
- FAB: 새 계획 추가

### 2. 지출 계획 등록/수정 폼
- 이름, 금액, 목표 날짜 (캘린더 선택)
- 카테고리 선택 (기존 카테고리 팝업 재활용)
- 결제수단 선택 (기존 결제수단 팝업 재활용)
- 예산 연결 (해당 카테고리의 예산 자동 제안)
- 반복 설정 토글
- 메모

### 3. 예산 탭 연동
- 예산 상세에 "계획된 지출" 섹션 추가
- 계획 금액 합계 vs 예산 금액 비교 표시
- 계획 진행률 바

### 4. 거래 추가 시 계획 매칭
- 거래 저장 직전, 매칭 계획이 있으면 바텀 시트로 제안
- "이 계획의 지출입니다" → 연결 + 계획 완료
- "아니요" → 일반 거래로 저장

### 5. 대시보드 위젯
- "오늘의 계획" 카드
- 기한 초과 알림 배지

## 성능 설계
- **데이터 접근**: couple_id + target_date 인덱스로 기간 조회 (주간: ~5-10건, 월간: ~20-30건)
- **예상 규모**: 가구당 월 10~30건 계획, 연간 ~360건 → 성능 이슈 없음
- **매칭 제안**: 카테고리 + 날짜 ±3일 + 금액 ±20% 조건으로 DB 쿼리, 결과 ~0-3건
- **예산 연동**: budget_id 인덱스로 해당 예산의 계획 합계 집계 (SUM WHERE budget_id = ?)
- **반복 계획**: 월초 스케줄러로 다음 달 계획 자동 생성 (RecurringTransaction 패턴 재활용)
- **리소스**: 추가 테이블 1개, 인덱스 3개, 쿼리 복잡도 낮음

## 기존 패턴과의 관계
| 기존 기능 | 관계 |
|----------|------|
| MonthlyBudget | spending_plan.budget_id로 연결, 예산 내 계획 금액 표시 |
| WeeklyBudgetSnapshot | 주간 뷰에서 해당 주 계획 표시 |

## 기획 검증 결과
### 기술적 타당성
- ✅ 기존 아키텍처(Clean Architecture + BLoC) 패턴 그대로 활용
- ✅ RecurringTransaction 스케줄링 패턴 재사용 가능
- ✅ Visibility/Ownership 모델 동일 적용
- ✅ 거래 매칭: 단순 조건 쿼리로 구현 가능 (ML 불필요)
- ✅ 예산 연동: budget_id FK로 간단한 집계

### 주의사항
- budget_id FK: monthly_budgets는 월별로 다른 row → 반복 계획 시 매월 새 budget_id 연결 필요
- linked_transaction_id: 1:1 관계 (1 계획 = 1 거래), 분할 결제는 향후 고도화
- OVERDUE 전환 타이밍: 앱 시작 시 or 백엔드 스케줄러 (서버 비용 고려)

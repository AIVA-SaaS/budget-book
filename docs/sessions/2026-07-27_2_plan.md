## 2. 스코프 감사 (변경마다 공통 적용 여부 먼저 — feedback_common_scope_audit)

"ADJUSTMENT 는 정산 대상이 아니다" 라는 **하나의 규칙**이 걸리는 지점 전수:

  `transactions.every((t) => t.isReconciled)` → 잔액 수정이 있는 날은 **영원히** 완료 점 미표시.
- FE-2 정산 뷰 미기록 목록 — 서버 필터 결과를 그대로 쓰므로 BE-4 로 해결(클라 재필터 금지).

## 3. 하네스 게이트 대응 (STRUCTURAL_FIX_REQUIRED)

`pre-change-audit.sh . "amount_calculation,ui_pattern,filter_propagation"` →
amount_calculation 3건 / filter_propagation 3건(전부 타 프로젝트·과거) → 패치 금지, 구조적 강제 필수.

- **S1 (amount_calculation, BE) — 컴파일 타임 강제.** `ReconciliationScope` 를 집계기 옆에 두고
  `when(type)` 을 **`else` 없이** 전부 나열한다. `TransactionType`/`TransferKind` 에 값이 추가되면
  **컴파일 에러**로 터져 "새 종류를 정산 대상에 넣을지" 판단을 강제한다.
  쿼리용 제외 목록은 손으로 쓰지 않고 `TransactionType.entries.filterNot(::isReconcilable)` 로
  **파생**시킨다 → 정의가 두 벌이 될 수 없다.
- **S2 (filter_propagation, BE) — 교차 엔드포인트 불변식 테스트.**
  "요약의 `unrecordedCount` == `GET /transactions?reconciled=false` 건수 + 미기록 이체 건수" 를
  ADJUSTMENT 가 섞인 픽스처 달에 대해 검증. 한쪽만 고치면 **테스트가 깨진다**
  (이번 버그가 정확히 "요약 건수는 맞고 행만 다른" 형태였다).
- **S3 (FE) — 규칙을 위젯 밖으로.** `lib/core/reconciliation/reconciliation_scope.dart` 에
  `isReconcilable(Transaction)` / `isReconcilable(Transfer)` 단일 정의. 달력·정산 뷰·향후 홈 위젯이
  전부 이걸 쓴다. 위젯 테스트로 "잔액 수정만 남은 날도 완료 점 표시" 고정.
- **S4 (ui_pattern)** — 인시던트 0건이지만 이번 어포던스 실패(⋮ 로 chevron 을 덮음)를
  하네스에 등록해 다음 회차부터 감지되게 한다.

### 4.5 인프라 — 정산 아이콘 미노출 (추가 요구 4, PR #251 과 동일 계열 재발)

**증상**: 정산 관련 아이콘(뷰 토글 `fact_check`, 배지 `check_circle` 등)만 빈칸.

**측정(hard evidence)**:
- 라이브 `/assets/fonts/MaterialIcons-Regular.otf` → `cache-control: public, max-age=31536000, immutable`
  (`infra/nginx/aiva-bb.conf:146`, `location ~* \.(ttf|otf|woff|woff2)$`).
- 그 URL 이 **실제로 서빙하는** 폰트의 cmap 에는 `fact_check`(0xe256), `check_circle`(0xe159),
  `verified`(0xe699), `calendar_month`(0xf06bb), `history`(0xe314), `swap_horiz`(0xe625) **전부 존재**
  (fontTools 로 확인, 291 글리프, last-modified 07-27 05:52).
→ 서버 산출물 정상. **클라이언트가 1년 immutable 로 물고 있는 이전 빌드의 트리셰이킹 서브셋**이 원인.

**인과 메커니즘**: Flutter web 은 `--tree-shake-icons` 로 매 빌드마다 **내용이 달라지는** 아이콘 폰트를
**해시 없는 고정 URL** 로 내보낸다. nginx 는 이 URL 을 `immutable` 로 표시 → 재방문 클라이언트는
재검증조차 하지 않는다 → **새로 추가된 아이콘만** 빈칸. PR #251 때 `main.dart.js` 는 no-cache 로
돌렸지만 폰트는 `:157` 주석대로 의도적으로 immutable 을 유지해 같은 함정이 폰트에서 재발했다.

11. `infra/nginx/aiva-bb.conf` — 폰트 location 의 `Cache-Control` 을
    `no-cache, must-revalidate` 로 교체(MIME override·gzip·access_log off 는 유지).
    주석의 잘못된 전제("빌드 산출물은 변경 시 새 URL")를 **"Flutter web 산출물은 해시 없는 고정 URL —
    immutable 금지"** 로 정정.
12. **S5 구조적 강제** — `infra/scripts/verify-cache-headers.sh` 신규 + `deploy-nas.yml` 배포 후 단계에 편입.
    해시 없는 산출물 목록(`/index.html`, `/main.dart.js`, `/flutter_bootstrap.js`,
    `/flutter_service_worker.js`, `/assets/fonts/MaterialIcons-Regular.otf`,
    `/assets/AssetManifest.bin.json`, `/assets/FontManifest.json`)을 curl 해
    `Cache-Control` 에 `immutable` 이 있거나 `no-cache` 가 없으면 **배포 실패**.
    → "새 산출물 유형이 추가될 때마다 캐시 정책을 빠뜨리는" 반복을 CI 가 막는다.
13. 이미 오염된 클라이언트는 헤더를 고쳐도 **immutable 특성상 만료 전 재검증하지 않는다** →
    사용자 1회 하드 리프레시(웹 Ctrl+Shift+R / 모바일 사이트 데이터 삭제)가 필요. 라이브 검증 안내에 포함.

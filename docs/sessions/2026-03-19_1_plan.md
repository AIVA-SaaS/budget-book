# 커플 초대 코드 상태 관리 개선
> 날짜: 2026-03-19 | 회차: 1 | 상태: 기획

## 요청 내용
커플 연결 > 코드 발급 > 연결 상태 확인 시:
- 기존 코드가 유지 중이면 연결 여부 + 잔여 시간 표시
- 만료 시 만료 문구 + 재발급 버튼
- 현재는 "연결 상태 확인" 클릭 시 미연결이면 코드 정보가 사라짐

## 현재 동작 (문제)
1. 코드 발급 → `CoupleInvitationPending(invitation)` 상태
2. "연결 상태 확인" 클릭 → `LoadCouple` 이벤트 → `getMyCouple()` API 호출
3. 미연결이면 404 → `CoupleNotLinked` 상태로 전환 → **코드 정보 소실**
4. 사용자는 코드가 아직 유효한지, 만료됐는지 알 수 없음
5. "새 코드 생성" 시 기존 코드가 자동 취소됨 (안내 없음)

## 영향 범위 분석
- **BE 변경**: 초대 상태 조회 API 추가 (1개 엔드포인트)
- **FE 변경**: BLoC 이벤트 핸들러 수정 + UI 상태 표현 개선
- 기존 API/로직 변경 없음 (추가만)

## 설계

### BE: 초대 상태 조회 API
```
GET /api/v1/couples/invitations/me
```
- 현재 사용자의 가장 최근 PENDING 초대를 조회
- 응답:
  - PENDING + 미만료 → `200 { code, expiresAt, status: "PENDING" }`
  - PENDING + 만료 → 서버에서 EXPIRED로 갱신 후 `200 { code, expiresAt, status: "EXPIRED" }`
  - ACCEPTED → `200 { code, expiresAt, status: "ACCEPTED" }`
  - 초대 없음 → `404 INVITATION_NOT_FOUND`
- Repository 추가: `findTopByInviterIdOrderByCreatedAtDesc(inviterId: UUID): CoupleInvitation?`

### FE: 상태 확인 플로우 변경
현재: "연결 상태 확인" → `LoadCouple` → 미연결 시 `CoupleNotLinked`

변경:
1. "연결 상태 확인" → 새 이벤트 `CheckInvitationStatus`
2. 먼저 `getMyCouple()` 호출 → 커플 연결됨이면 `CoupleLinked`
3. 미연결이면 `getMyInvitation()` 호출 → 초대 상태 확인
   - PENDING + 유효 → `CoupleInvitationPending(invitation)` 유지 (잔여 시간 갱신)
   - EXPIRED → 새 상태 `CoupleInvitationExpired(invitation)` 표시
   - 없음 → `CoupleNotLinked`

### FE: 새 상태 추가
```dart
class CoupleInvitationExpired extends CoupleState {
  final Invitation invitation;
  const CoupleInvitationExpired(this.invitation);
}
```

### FE: UI 변경
**만료 상태 화면** (`CoupleInvitationExpired`):
- 만료 아이콘 + "초대 코드가 만료되었습니다" 문구
- 만료된 코드 표시 (흐리게)
- "새 코드 발급" 버튼 (FilledButton)
- "코드로 연결" 입력 영역 (상대가 먼저 코드를 보낸 경우)

**대기 상태 화면** (`CoupleInvitationPending`): 기존 유지 + 잔여시간 실시간 갱신

## 성능 설계
- **데이터 접근**: `findTopByInviterIdOrderByCreatedAtDesc` — inviter_id 인덱스 활용, 단일 행 조회
- **예상 규모**: 초대는 사용자당 극소수 (1~2건), 성능 이슈 없음
- **리소스 제약**: 추가 인덱스 불필요 (inviter_id FK 인덱스 존재)

## §5.4 실패 처리

### C. 폰트 실패 원인 분석
- **1차 시도 (#153) 실패**:
  - Flutter web asset URL 은 `/assets/assets/fonts/` (중복 /assets/) 인데 location prefix 를 `/assets/fonts/` 로 작성 → 매칭 실패
  - nginx 기본 types 가 .ttf 를 `application/octet-stream` 서빙 → gzip_types(font/ttf) 매칭 실패 → gzip 미적용
  - 실제 파일 크기 10MB (추정 2.2MB 아님)
- **2차 fix (#154)**:
  - `location ~* \.(ttf|otf|woff|woff2)$` 확장자 정규식 매칭
  - `types {}` 블록으로 Content-Type 강제 override
  - Cache-Control long-term immutable
- **배포 후 curl 헤더 검증**:
  ```
  content-type: font/ttf ✅
  content-encoding: gzip ✅
  cache-control: public, max-age=31536000, immutable ✅
  vary: Accept-Encoding ✅
  ```

### R. 재정렬 버그 원인 분석
- ReorderableListView onReorder 로직:
  1. 리스트 끝 드롭(`newIndex == length`) 시 기존 루프가 매칭 못해 `methodNewIndex` 기본값 0 → 맨 앞으로 이동
  2. type 경계 이동 방지 없음 → 드롭 시 type 섞이지만 BE 는 type 변경 안 해 재로드 시 그룹핑 깨짐
- 수정:
  - Flutter 표준 규약대로 visual newIndex 먼저 보정 (↓이동 -1)
  - 같은 type 내 이동만 허용 (type 비교 → 다르면 no-op)
  - visual→method index 변환 루프 재작성, end-of-list 경계 명시 처리

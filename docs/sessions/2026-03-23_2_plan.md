# Budget Book 백엔드 NAS 이전
> 날짜: 2026-03-23 | 회차: 2 | 상태: 기획

## 요청 내용
Render free tier 제한(빌드 분 소진, cold start, 느린 배포)으로 자작 NAS로 백엔드 이전

## 현재 상태
```
NAS (tiggle.duckdns.org)
├── :80   → tiggle FE
└── :8080 → tiggle BE

Render (budget-book-api.onrender.com)
└── budget-book API (Spring Boot) → 빌드 분 소진으로 배포 불가

GitHub Pages (aiva-saas.github.io/budget-book)
└── budget-book FE (Flutter Web) → 유지
```

## 핵심 제약
- **HTTPS 필수**: Google/Kakao OAuth2가 HTTPS redirect URI 요구
- **포트 80 사용 중**: tiggle FE가 사용 → Let's Encrypt HTTP-01 challenge 불가
- **DuckDNS**: DNS-01 challenge로 SSL 발급 가능

## 작업 계획

### Step 1: DuckDNS 서브도메인 등록
- https://www.duckdns.org 에서 `budget-api` 등록 (같은 IP)
- 결과: `budget-api.duckdns.org` → NAS IP

### Step 2: 라우터 포트포워딩
- 443 → NAS (HTTPS, Caddy 리버스 프록시용)

### Step 3: Docker Compose 배포
```
NAS Docker
├── caddy (리버스 프록시 + 자동 HTTPS)
│   ├── :443 budget-api.duckdns.org → budget-book-api:8080
│   └── DNS-01 challenge (DuckDNS)
├── budget-book-api (Spring Boot)
│   └── :8080 (내부)
├── postgres (DB)
│   └── :5432 (내부)
└── redis (선택, 캐시)
    └── :6379 (내부)

기존 유지 (변경 없음)
├── :80   → tiggle FE
└── :8080 → tiggle BE (외부 포트 다르게 설정 필요)
```

> **주의**: tiggle BE도 8080이므로, budget-book-api는 내부 포트 8090 사용 또는
> Docker 네트워크로 분리하여 충돌 방지

### Step 4: OAuth2 설정 변경
- Google Console: redirect URI → `https://budget-api.duckdns.org/login/oauth2/code/google`
- Kakao Developers: redirect URI → `https://budget-api.duckdns.org/login/oauth2/code/kakao`

### Step 5: 프론트엔드 API URL 변경
- `frontend/lib/core/constants/api_constants.dart` 또는 환경변수
- `https://budget-book-api.onrender.com` → `https://budget-api.duckdns.org`

### Step 6: DB 마이그레이션
- 옵션 A: Supabase 유지 (외부 DB, NAS에서 접속)
- 옵션 B: NAS PostgreSQL로 이전 (Supabase 데이터 pg_dump → restore)
- **추천: 옵션 B** (완전 자체 호스팅, 지연 시간 최소)

## 장점 비교

| 항목 | Render Free | NAS |
|------|------------|-----|
| 빌드 분 | 월 제한 | 무제한 |
| Cold start | 15분 비활성→sleep | 없음 (항상 실행) |
| 배포 속도 | 5~10분 | 1~2분 (로컬 빌드) |
| 메모리 | 512MB | NAS 여유분 |
| 비용 | 무료(제한적) | 전기세만 |
| 안정성 | Render 의존 | 자가 관리 |

## 성능 설계
- **메모리**: JVM 512MB~1GB 권장 (NAS 여유분에 따라)
- **DB**: PostgreSQL 로컬이면 네트워크 지연 0ms (현재 Supabase ~100ms)
- **배포**: `docker compose up -d --build` 한 줄로 완료

## 영향 범위 분석

### KI-001: 날짜 팝업 — 헤더 없는 캘린더
**분석**: `DatePickerEntryMode.calendarOnly`는 텍스트 입력 전환만 제거, Material3 헤더는 그대로 남음.
**해결**: Flutter 내장 `CalendarDatePicker` 위젯을 커스텀 Dialog에 감싸서 사용. 외부 패키지 불필요.

```dart
Future<DateTime?> showCalendarOnlyPicker(BuildContext context, DateTime initial) {
  return showDialog<DateTime>(
    context: context,
    builder: (ctx) {
      DateTime selected = initial;
      return Dialog(
        child: ConstrainedBox(
          constraints: BoxConstraints(maxWidth: 360, maxHeight: 400),
          child: Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              Padding(
                padding: EdgeInsets.fromLTRB(16, 12, 8, 0),
                child: Row(
                  children: [
                    Text('날짜 선택', style: TextStyle(fontSize: 16, fontWeight: FontWeight.bold)),
                    Spacer(),
                    IconButton(icon: Icon(Icons.close), onPressed: () => Navigator.pop(ctx)),
                  ],
                ),
              ),
              CalendarDatePicker(
                initialDate: initial,
                firstDate: DateTime(2020),
                lastDate: DateTime(2030, 12, 31),
                onDateChanged: (d) => selected = d,
              ),
              Padding(
                padding: EdgeInsets.all(8),
                child: ElevatedButton(
                  onPressed: () => Navigator.pop(ctx, selected),
                  child: Text('선택'),
                ),
              ),
            ],
          ),
        ),
      );
    },
  );
}
```

**변경 파일**: 공용 위젯으로 `core/widgets/calendar_picker_dialog.dart` 생성, 전체 10곳의 `showDatePicker` 교체.

### KI-002: 거래 추가 폼 — 상단 3탭 (지출/수입/이체)
**분석**: 현재 FAB → BottomSheet(3선택지). 사용자는 폼 자체에 탭을 원함.
**설계**:
- `TransactionFormPage`에 상단 `TabBar` 추가: [지출 | 수입 | 이체]
- 지출/수입: 기존 거래 폼 (type 전환)
- 이체: 기존 `TransferFormPage`의 내용을 탭 뷰로 통합 (별도 페이지 대신 같은 폼에)
- FAB 클릭 → `/transactions/create` (기본 지출 탭)
- 홈 퀵액션: 수입 클릭 → `/transactions/create?tab=income`, 이체 → `/transactions/create?tab=transfer`

**변경 파일**:
- `transaction_form_page.dart` — TabBar + TabBarView 추가, 이체 폼 통합
- `dashboard_page.dart` — 퀵액션 네비게이션 수정 (BottomSheet 제거)
- `transaction_list_page.dart` — FAB 네비게이션 수정 (BottomSheet 제거, 바로 폼으로)
- `main_shell_page.dart` — FAB 동작 수정

### KI-003: 홈 탭 위젯 커스터마이징
**분석**: 대시보드 위젯이 하드코딩. `project_home_customization.md` 기획 있으나 미구현.
**설계**:
- `DashboardWidgetConfig`: 위젯 ID, 이름, 활성화 여부, 순서
- 기본 위젯 목록: 요약카드(필수), 예산사용현황, 최근거래, 결제수단별현황, 자산현황, 개인거래
- SharedPreferences에 설정 저장 (서버 불필요, 기기별 설정)
- 설정 페이지에 "홈 화면 구성" 메뉴 → 드래그 순서 변경 + ON/OFF 토글
- **자산 현황**: 기본 OFF

**변경 파일**:
- `dashboard_page.dart` — 위젯 순서/가시성을 config 기반으로 렌더링
- 신규: `settings/pages/home_config_page.dart` — 드래그+토글 설정 UI
- 신규: `home/domain/dashboard_widget_config.dart` — 위젯 설정 모델
- `settings_page.dart` — "홈 화면 구성" 메뉴 추가

### KI-004: 홈 탭 주간 예산 금액 불일치
**분석**: 홈 대시보드와 예산 탭 **모두 동일한 API** (`GET /api/v1/budgets/summary`) 사용 확인.
- `BudgetService.getBudgetSummary()`는 이미 WEEKLY pro-rata 수정 완료.
- 사용자가 보는 100만원은 **이전 배포(수정 전)**의 캐시 또는 **NAS에 배포된 최신 코드**에서 아직 반영 안 된 상태일 수 있음.
- 방금 NAS에 최신 코드 배포 완료 → 새로고침 시 정상 표시될 것.

**검증 필요**: NAS 배포 후 실제 API 응답에서 WEEKLY 예산의 budgetAmount가 일할 계산되었는지 curl로 확인.

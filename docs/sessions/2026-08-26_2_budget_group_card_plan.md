## 0. 요구 (사용자 문장 그대로)

> "높이 조정이 잘 됐다. 근데 **상위 총 예산에 각 예산항목이 묶이는 개념**이기 때문에
> **펼치기/숨기기 가능한 구조**여야하고 **UI도 그렇게 엮여야**할 것 같은데 지금은
> **별도로 떨어진 것 처럼** 되었다. 위 기조는 이전과 동일하게 가져가고,
> **높이는 지금 변경된거 유지**해줘"

★7차 요구(행 간 높이 동일성)는 **달성됐고 유지한다**. 이번은 **다른 축**이다 — 계층 관계.

## 1. 원인 (실측)

- `[측정: 코드]` `budget_list_page.dart:_buildLoaded` 는
  `Column[MonthNavigator, BudgetSummaryCard, Expanded(ListView(항목들))]` 이다.
  **총 예산 카드와 항목 리스트가 형제**이고, 항목들끼리도 평평한 형제다.
  계층을 표현하는 장치가 **하나도 없다**(들여쓰기·테두리·접기 전무).
- `[측정: 코드]` 정렬이 어긋났다:
  - `BudgetSummaryCard` = `Card(margin: horizontal 16)` → 바깥선 x=**16**, 내용 x=**32**
  - 종전 항목(`ListTile`) = 기본 `contentPadding` horizontal **16** → 내용 x=**16**
    (= 카드 바깥선과 같은 줄)
  - 현재 항목(`EntityTileRow`) = `space.xl` ≈ **10.2**(모바일 390px) → 내용 x=**10.2**
- `[추론]` 즉 7차 이관으로 항목이 카드보다 **5.8px 더 바깥으로** 나갔다. 종전에도 계층
  표현은 없었지만 최소한 카드 바깥선과 줄이 맞아 "아래 딸린 목록"으로 읽혔고, 지금은
  카드보다 넓어져 **별개 블록**으로 읽힌다. 유도 과정: 바깥선 16 vs 내용 10.2 → 항목이
  카드 좌우로 각각 5.8px 삐져나온다.
- ★따라서 이번 결함은 **7차가 만든 것(정렬 5.8px)과 원래 없던 것(계층 표현)이 겹친 것**이다.
  정렬만 되돌리면 "덜 나빠지"지만 요구("묶이는 개념")는 충족되지 않는다.

## 2. 처방 — 승인된 형태

`BudgetSummaryCard` 와 항목들을 **하나의 `Card`** 안에 넣는다.

```
Card(margin: h16 v8)
 └ Column
    ├ 헤더  : 이번 달 예산 · 총액 · 진행바 · 지출/남음 · ▾ 토글   (현행 내용 그대로)
    ├ Divider                                            (펼친 상태에서만)
    └ 항목들 : BudgetTile × N                             (펼친 상태에서만)
```

- **접기/펼치기**: 헤더 우측 `▾`/`▴`. 기본 **펼침**. 상태는 `_BudgetListPageState` 보유(이미 `StatefulWidget` 이다 `[측정: 코드]`).
- **정렬**: 항목 내용이 헤더 텍스트와 **같은 줄**(카드 내부 x=32)에 오도록 항목 좌우에
  `16 − space.xl` 를 더한다. 매직 넘버로 적지 않고 **토큰 산술**로 적는다.
- **높이 불변**: `EntityTileRow`·`BudgetTile` 은 **건드리지 않는다**. 7차 계약
  (`박스 = max(잉크 + 2 × xs, 슬롯 44)` · 프로그레스 자리 항상 예약)이 그대로 유효하고,
  7차 가드가 편차 **0.00px** 로 그것을 지키고 있다 `[측정]`.
- **스크롤**: 카드가 항목을 품으므로 카드는 `ListView` 의 **첫 자식**이 된다
  (종전엔 `Expanded` 밖에 고정돼 있었다 `[측정: 코드]`). 그래야 목록이 길어져도 함께 스크롤된다.
- **커플 모드 `나만 보임` 섹션**: 같은 카드 안에 소제목으로 유지한다. 그 섹션은
  `_buildBudgetList` 안에 `isCoupleMode()` 분기로 실재한다 `[측정: 코드]`.

## 3. 구조적 수정 (`ui_pattern` STRUCTURAL_FIX_REQUIRED — 패치 불허)

계층을 "여백으로 흉내내는" 처방은 채택하지 않는다. 관계를 **컨테이너가 소유**하게 한다.

- **S1 — 관계를 컨테이너로 표현한다**: 항목이 카드의 **자식**이 된다. 부모-자식이
  위젯 트리에 실재하므로 여백 값이 바뀌어도 관계가 깨지지 않는다.
- **S2 — 접기 상태의 단일 소유자**: 펼침 여부는 `_BudgetListPageState` 필드 하나가
  가지고, 헤더 토글과 항목 렌더가 **같은 값**을 읽는다(두 곳에서 판정하지 않는다).
- **S3 — 정렬을 산술로 고정**: 항목 인셋 = `16 − space.xl`(카드 내부 정렬). 리터럴
  금지 — 토큰이 바뀌면 인셋도 따라 바뀌어야 한다.
- **S4 — 소스 봉인**: `_buildLoaded` 에서 `BudgetSummaryCard` 가 `ListView` **밖**
  형제로 돌아가지 않는다(그 순간 관계가 다시 끊긴다).

★2026-07-27 교훈 적용 `[측정: 교훈대장]`: `ExpansionTile.trailing` 을 다른 위젯으로 덮어써
**펼침 chevron 자체가 사라진** 인시던트가 있었다. 그래서 `ExpansionTile` 을 쓰지 않고 **헤더 행에
chevron 을 명시적으로** 둔다(다른 액션이 그 자리를 덮을 수 없다).

## 5. 축 ↔ 가드 매핑

- 항목이 카드의 **자손**이다 → **신규** 위젯 테스트(`find.descendant(of: Card, ...)`)
- 토글이 항목을 **숨기고/보인다** → **신규** 위젯 테스트(탭 → findsNothing → 탭 → findsN)
- 항목 내용이 **헤더 텍스트와 같은 x** → **신규** 정렬 측정(허용오차 0.5dp)
- **행 간 높이 동일성 무회귀** → 기존 `budget_row_height_guard_test`(7차, 편차 0.00) +
  카드 안에서도 동일함을 신규 케이스로 재확인
- 행 안 위/아래 균형 무회귀 → 기존 `row_balance_guard_test`
- `BudgetSummaryCard` 가 `ListView` 밖으로 돌아가지 않는다 → **신규** 소스 봉인
- **체감(묶여 보이나 · 접기가 자연스럽나)** → `[무가드]` 사용자 라이브

**대조군 의무(V3)**: 신규 가드는 변경 전 코드에서 **1회 실패**시키고 건수를 대장에 남긴다.

## 8. 미해결 사항

1. **접기 상태를 세션 간 기억할지 `[미확인]`.** 1차는 **매번 펼침**으로 둔다(놀람 최소).
   확인 주체 = 사용자. "접어두면 계속 접혀 있길 바란다" 회신이 오면 `PageStorage` 로 옮긴다.
2. **커플 모드에서 `나만 보임` 섹션을 별도로 접을지 `[미확인]`.** 1차는 **총 예산 토글 하나**만
   둔다(요구가 "상위 총 예산"이라 단수였다). 확인 주체 = 사용자.
3. **항목이 20+ 일 때 카드가 화면보다 길어지는 체감 `[미확인]`.** 스크롤은 되지만
   카드 경계가 화면 밖으로 나가 "묶임"이 약해질 수 있다. 확인 수단 = 사용자 라이브.
   완화안(헤더 sticky)은 이번 범위 밖이다.
4. **`전체 예산`(카테고리·그룹 없음) 행이 실제로 존재하는지 `[미확인]`.**
   `targetLabel` 에 그 분기가 실재한다 `[측정: 코드]` — 운영 데이터에서 본 적은 없다 `[미확인]`. 있으면 그 행이
   카드 안에서 총액과 중복돼 보일 수 있다. 확인 수단 = 라이브 화면 또는 운영 DB 조회.

# 보험 연동 + 고정지출 자동관리 기능 (확장 설계)
> 날짜: 2026-03-19 | 회차: 4 | 상태: 기획 (추후 고도화 예정)

## 요청 내용

### 1. 보험 청구 트래킹
병원/약국 지출 시 실비 보험 청구와 연결하여:
- 원래 지출액 → 보험 환급액 → 실제 부담액 자동 계산
- 보험 청구 상태 관리 (미청구 → 청구 완료 → 환급 완료)
- 과거 유사 치료의 환급 이력 참고 가능

**사용자 시나리오**:
```
1. 병원에서 염증 주사 맞음 → 58,100원 지출 거래 등록
2. 실비 보험 청구 연결 → 청구 상태: "청구 완료"
3. 보험금 입금 → 33,600원 환급 입력
4. 표시: 58,100원 ~~취소선~~ → 실제 부담 24,500원
5. 통계: 총 의료비 58,100 | 보험 환급 33,600 | 실부담 24,500
```

### 2. 고정지출/보험료 자동 갱신 관리
- 보험료, 구독 서비스, 월세 등 자동 결제 항목 통합 관리
- 갱신일 알림 (보험 갱신, 구독 갱신 등)
- 갱신 시 금액 변동 트래킹

## 설계 방향

### 데이터 모델: 보험 청구 (InsuranceClaim)

```
insurance_policies (보험 목록)
├── id, couple_id, owner_id
├── name (예: "메리츠 실비보험")
├── type (REAL_EXPENSE / LIFE / AUTO / ...)
├── provider (보험사)
├── policy_number (증권번호, optional)
├── monthly_premium (월 보험료)
├── renewal_date (갱신일)
├── is_active
└── created_at, updated_at

insurance_claims (보험 청구)
├── id, policy_id, transaction_id
├── claim_amount (청구 금액)
├── refund_amount (환급 금액, nullable → 미입금)
├── status (PENDING / CLAIMED / REFUNDED / REJECTED)
├── claimed_at (청구일)
├── refunded_at (환급일, nullable)
├── notes (메모)
└── created_at, updated_at
```

### 거래와의 연결
```
Transaction (58,100원 병원비)
  └── InsuranceClaim
        ├── policy: 메리츠 실비보험
        ├── claim_amount: 58,100
        ├── refund_amount: 33,600
        ├── status: REFUNDED
        └── actual_cost: 24,500 (= 58,100 - 33,600)
```

### 고정지출 통합 관리 시스템

고정지출은 성격이 매우 다양하므로 **유형별 분류 체계**가 핵심.

#### 고정지출 분류 체계

| 유형 | 기한 | 갱신 | 금액변동 | 예시 |
|------|------|------|---------|------|
| **보험료** | 갱신 주기 | 연/2년/3년 | 갱신 시 변동 | 실비보험, 차량보험, 생명보험 |
| **계약형** | 계약 기간 | 만료 후 재계약 | 재계약 시 변동 | 월세, 전세이자, 학원비 |
| **구독형** | 없음(해지까지) | 없음 | 인상 가능 | 넷플릭스, 쿠팡, 유튜브 |
| **공과금** | 없음 | 없음 | 매월 변동 | 수도세, 전기세, 가스비, 관리비 |
| **교통/통신** | 약정 기간 | 약정 만료 | 약정 후 변동 | 교통카드, 통신비, 인터넷 |
| **할부** | 잔여 개월 | 없음(완납) | 고정 | 자동차 할부, 가전 할부 |

#### 데이터 모델: 고정지출 (FixedExpense)

```
fixed_expenses (고정지출 마스터)
├── id, couple_id, owner_id, visibility
├── name (예: "월세", "메리츠 실비보험")
├── category_id (카테고리 연결)
├── payment_method_id (결제수단 연결)
│
├── type (INSURANCE / CONTRACT / SUBSCRIPTION / UTILITY / TRANSPORT / INSTALLMENT)
├── amount (기본 금액 — 공과금은 예상 금액)
├── is_variable_amount (금액 변동 여부: 공과금=true, 보험료=false)
│
├── billing_day (결제일: 매월 N일)
├── billing_cycle (MONTHLY / BIMONTHLY / QUARTERLY / SEMIANNUAL / ANNUAL)
│
├── -- 기간 관련 --
├── has_term (기한 유무: 보험/계약/할부=true, 구독/공과금=false)
├── start_date (시작일)
├── end_date (종료/만료일, nullable)
├── remaining_months (잔여 개월, 할부용)
│
├── -- 갱신 관련 --
├── has_renewal (갱신 유무: 보험/계약=true, 구독/공과금=false)
├── renewal_cycle (ANNUAL / BIANNUAL / TRIANNUAL, nullable)
├── renewal_date (다음 갱신일, nullable)
├── renewal_alert_days (갱신 N일 전 알림, default 30)
│
├── -- 보험 전용 --
├── insurance_policy_id (보험 정책 연결, nullable)
│
├── is_active
├── notes (메모)
└── created_at, updated_at

fixed_expense_history (금액 변동 이력)
├── id, fixed_expense_id
├── amount (변동 후 금액)
├── previous_amount (변동 전 금액)
├── reason (변동 사유: "갱신", "인상", "재계약" 등)
├── effective_date (적용일)
└── created_at
```

## 구현 단계 (예상)

### Phase 1: 고정지출 기반
- DB: `fixed_expenses`, `fixed_expense_history` 테이블
- BE: 고정지출 CRUD API (6가지 유형 지원)
- FE: 고정지출 관리 화면 (유형별 섹션 분리)
- 기존 `recurring_transactions` → `fixed_expenses` 연동 (자동 거래 생성)

### Phase 2: 보험 기본
- DB: `insurance_policies`, `insurance_claims` 테이블
- BE: 보험 CRUD + 청구 연결 API
- FE: 보험 목록/추가, 거래에 보험 청구 연결
- 보험료 → 고정지출 자동 등록

### Phase 3: 환급 트래킹
- 환급 입력 → 거래 실부담액 자동 계산
- 거래 상세에 보험 정보 표시 (취소선 + 실부담)
- 통계에 의료비/환급/실부담 분리

### Phase 4: 갱신 + 알림
- 갱신일 관리 (보험, 계약형)
- 만료/갱신 N일 전 알림 (push 또는 앱 내)
- 할부 완납 알림

### Phase 5: 공과금 변동 관리
- 매달 금액 입력 UI
- 월별 추이 그래프
- 3/6개월 평균 자동 계산

### Phase 6: 인사이트
- 유사 치료 환급 이력 추천
- 보험 환급률 분석
- 고정지출 월별 추이 + 전월 대비
- 연간 고정지출 총액 + 비중 분석

## 성능 설계
- **고정지출**: couple당 20~50건 예상, 단순 조회 → 성능 이슈 없음
- **보험 청구**: 거래당 0~1건, JOIN으로 조회 → 인덱스 `(transaction_id)` 충분
- **금액 변동 이력**: fixed_expense_id 인덱스로 조회, 항목당 연 12건 이하
- **유사 치료 이력**: 카테고리 + 설명 유사도 기반 검색 → `LIKE` 또는 full-text search
- **통계**: 기존 통계 쿼리에 보험 환급 LEFT JOIN 추가

## 기술적 고려사항
- 보험/고정지출은 **visibility** 적용 — 개인 보험은 PRIVATE, 공과금/월세는 SHARED
- 환급 입력 시 거래 금액은 변경하지 않음 (원래 지출액 유지, 환급은 별도 추적)
- 알림 시스템 필요 (push notification 또는 앱 내 알림)
- 고정지출 ↔ recurring_transactions 연동: 고정지출 등록 시 반복거래 자동 생성
- 공과금 변동형: 매달 실제 금액 입력 → history에 기록 → 평균 자동 갱신

## 확장성 설계 원칙
- **새 유형 추가 용이**: `type` enum만 추가하면 새 고정지출 유형 지원
- **금액 변동 이력 공통**: 모든 유형에 `fixed_expense_history` 사용
- **갱신/만료 공통 로직**: `has_renewal`, `has_term` 플래그로 유형별 동작 분기
- **보험 청구는 별도 모듈**: `insurance_claims`는 보험 전용, 다른 고정지출에 영향 없음
